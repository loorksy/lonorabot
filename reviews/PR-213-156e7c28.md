## Findings

### L1 (low): «حسم العملية» is a dead button when the Settle card is drawn as a slot
- Where: `apps/mobile/app/thread.tsx:901-913` (`openOrder` → `onResolve`)
- Evidence:
  - The button is offered whenever a pending `resolve_operation` card exists for the operation (looked up in `ownerActions`).
  - The jump looks only for the standalone row: `timelineRef.current.findIndex((item) => item.id === \`owner_action:${settle.id}\`)`, and when it finds nothing, `if (index < 0) return;`.
  - `conversationTimeline` drops that row whenever a message embeds `settle:<id>` (`packages/core/src/conversation-timeline.ts:64`), and mobile draws such slots.
  - So with the Settle card in a slot, the tap does nothing and the sheet stays open. On web, the `[data-owner-action=id]` jump reaches the card inside the slot.
  - It settles nothing, so there is no money or safety effect.
  - The code comment ("the sheet stays, and the card is where the agent put it") describes the no-op, but the owner is not taken there.
- Fix:
  - When `index < 0`, find the message whose drawn content embeds `settle:${settle.id}` (core `embeddedSlots`). Scroll to that message's row and close the sheet.
  - Or pass `onResolve` as undefined when neither the row nor such a message exists.
  - Add an Expo case where an assistant message embeds the Settle slot.

### L2 (low, 0.4 / 14.1.3): the new spec carries a grant branch it never uses
- Where: `tests/mobile/order-line.spec.mjs:26-37` (`seedCard`)
- Evidence:
  - `seedCard` has a whole `grant_authority` path: `GrantDraft`, `DailyLossDraft`, `with_delegation('full')`.
  - The only call (`:194`) seeds a `resolve_operation` card.
  - New test code that spells out the grant and delegation vocabulary that phase 3 removes extends removed concepts for no use.
- Fix: drop the `grant_authority` branch.
