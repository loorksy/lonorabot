## Findings

### H1. A transient broker error permanently removes a symbol's currencies from the picture (5.4)
- `packages/trading/src/lonora_trading/picture.py:183-185`: `except LonoraError: found[symbol] = []`, with the comment "the broker reports no such instrument".
- MetaApi's `instrument()` (`packages/adapters/src/lonora_adapters/brokers/metaapi.py:467-480`) wraps every exception through `diagnose`/`provider_error` into a `LonoraError` (rate limit 429, timeout 504, credentials rejected…). So the "transport failure, retry next pass" branch is never reached for MetaApi.
- The stored `[]` is never retried until the account identity changes. The symbol then leaves `currencies_unknown`, shows `"currencies": []`, and drops out of `by_currency`. The prompt does not explain `[]`.
- Up to 20 per-symbol RPCs per pass make a rate limit likely.
- Reproduced by the subagent's probe: `broker_rate_limited` on the first pass; the second pass learned 0, and the picture showed `EURUSD currencies: []`, `by_currency: []`. Confirmed by reading both sites.
- Fix:
  - store `[]` only for a definitive not-found code (for example `symbol_not_found` or `broker_instrument_unavailable`, or status 404);
  - `continue` on every other `LonoraError`;
  - list `[]` symbols under `currencies_unknown`, or explain `[]` in the frame text;
  - add a test where a 429 is followed by learning on the next pass.

### M1. Tickets on symbols cut by `MAX_TEAM_SYMBOLS` vanish uncounted (5.4 "the whole team's", 0.4)
- `packages/agent-runtime/src/lonora_agent/context/picture.py:173-174`: `positions_not_shown` and `orders_not_shown` count only tickets beyond the 30 largest.
- Tickets on symbols dropped at `listed = symbols[:MAX_TEAM_SYMBOLS]` are neither rendered nor counted. Their currencies are also missing from `by_currency`. The frame's claim that the not_shown counts give the rest is untrue.
- Reproduced by the subagent's probe: with 21 symbols and 1 position each, 20 positions were shown with `positions_not_shown: 0` and `symbols_not_shown: 1`. Confirmed by reading the code.
- Fix:
  - set `positions_not_shown = len(positions) - sum(len(s["positions"]) for s in by_symbol)`, and the same for orders;
  - build `by_currency` from all symbols (counts only), or add the currencies of the symbols not shown;
  - add the 21×1 case to `tests/check_team_picture.py`.

### L1. Crypto quoted in USDT loses its base leg
- `trading/picture.py:39`: `CURRENCY_CODE = ^[A-Z]{3}$`. So `instrument_legs("BTC", "USDT")` returns `["USDT"]`, and BTC is lost, against "each leg of a pair". Confirmed by reading the code.
- Fix: accept `^[A-Z0-9]{3,5}$` (keep refusing base == quote) and add BTCUSDT to the unit cases.

### L2. The module docstring is untrue at this commit (0.4)
- `trading/picture.py:1-7` says the picture is built "never from a broker read". `learn_currencies` in the same module now reads instrument metadata from the broker.
- Fix: say that tickets come from the stored snapshot, and that instrument currencies come from a separate background broker read kept on the connection row.

### L3. One pass can outlive the step timeout
- `gateway/service.py:52`: `StepSpec("instrument_currencies", 30, 120)`. Each symbol gets a 20 s timeout, and up to 20 symbols per account are read before any write, so the worst case is 400 s, more than 120 s. A cancelled step loses everything that pass learned.
- Unverified at run time; it is arithmetic from the code.
- Fix: persist per symbol (or per small batch), or bound one pass to fit within 120 s.

## Rejected (one line each)
- Identity race in the currency cache (read outside the transaction, stamped at write): not reproduced. Note it for hardening: capture `account_identity` when the work list is built and skip the write on a mismatch.
- Calendar events (5.4 third bullet): not claimed here; this is W-PICTURE's step 4.
- Unpruned cache growth: bounded by the broker's symbol catalogue.
- The `observed_at` stamp on a disconnected snapshot is the same defect as #108 M1; one fix covers both.

- **Safety core.** Untouched; the new step takes no send lock. Writes to the connection row use `with_for_update` and `populate_existing` and merge the state.
