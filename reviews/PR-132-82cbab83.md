## Finding 1 (medium, 6.10): runs tainted by their trigger, and routine chains, are not marked

- `packages/tools/src/lonora_tools/profile_taint.py:41-46` marks only when `run_read_others(...)` is true. For a non-owner run, `external_content_seen(session, run, run.input_seq)` checks an empty message range (`restrictions.py:83-93`). So a Lonora run started by a peer, follow-up, tickets or webhook trigger (full tool scope) creates unmarked routines. A run woken from a marked routine also creates unmarked routines.
- Probe at this head (re-run by me):
  - `TRIGGER peer CREATE ok MARKED False WAKE_WRITE True`
  - the same for webhook, follow_up and tickets
  - `CHAIN A MARKED True`, then `CHAIN B CREATE ok MARKED False WAKE_WRITE True`
- A peer's or a team agent's outcome text can therefore have Lonora schedule a routine that later writes the shared owner model.
- `docs/agent-memory-and-recall.md:112-115` claims rows "such a Run created" keep the receipt, which is false for these runs (0.4).
- Fix: move `OBSERVATION_TRIGGERS` into `profile_taint.py` and add `profile_tainted(session, run)`: trigger not in `OBSERVATION_TRIGGERS`, or `run_read_others`, or woken by a marked row. Use it in both `mark_from` and `memory._owner_message`. Add the peer, follow-up and chain cases to the test.
