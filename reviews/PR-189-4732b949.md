## What I checked
- **Mandate:**
  - 14.3.11 keeps `DELETE /secrets/{secret_id}` as the only route that deletes a stored secret. The route stays, and the chat tool calls the same single function, `delete_secret`, which the route's store now uses too. No second deletion logic.
  - The chat path is what the lead's phase-4 map asks for at 14.3.11 ("needs a chat path and a guard for secrets in use"), and P5 asks for it. No screen is added.
- **Values never returned:**
  - `secrets_list` returns names, `updated_at` and the connections (kind and name) that name each secret. It returns no value and no id, and only the `workspace` scope: broker, provider and integration rows are never listed, and broker sessions are skipped.
  - Every connection payload it reads has `type` and `name` by contract (`Integration`, `McpConnection`).
- **Who may delete:**
  - `secret_delete` requires `owner_message_id`, which is None for a wake, a routine, or any run that read a web page, feed, MCP result or another agent's message.
  - The owner's own messages in this Run (the starting one and steering added while it ran; `origin == "owner"`, so never a card send) must name the secret as a whole word sequence.
  - The run lease is taken with a lock, and an effect receipt makes a replay answer as before.
  - Only `workspace` secrets are found by name, so a broker or provider value can never be deleted here.
- **In use:** `delete_secret` locks the secret row `FOR UPDATE` and refuses with `secret_in_use` while a broker session (also by its password), an integration or an MCP connection names it. This is the same guard as the route. Redaction keeps given values through `ln_workspace_given`, which deletion does not touch.
- **Text and UI:**
  - Tool labels are in Arabic and English (`turn-activity.ts`), and the manifest is regenerated (5.8.6).
  - Docs and docstrings are true at this commit (`restrictions.py`, `agents-from-chat.md`, `trusted-sources.md`).
- **Safety core (Section 6):** untouched.
- **Tests:** test_secret_chat, test_context_engine, test_release_manifest, test_secret_card, test_secret_redaction, test_broker_secret_boundary, test_capability_exposure and the tests touching the secrets route and `owner_message_id` give 174 passed. ruff is clean.

## Rejected findings
- The name check proves the owner named the secret, not that he asked for deletion (for example "do not delete API_KEY"). This is by design, the same rule as a model switch naming the model: an untainted owner run, and intent judged by the agent. Not a defect.
