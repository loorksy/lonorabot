## Verified findings

### M1 (medium): the first update to this release, and every start on an install that listed the overlay, still waits on web search

Commit 21a82b56 claims "Never wait on web search when lonora starts, restores or updates", and `docs/open-web-research.md` says "The gateway does not wait for them". Two paths contradict this.

1. **The transition update runs the old script.**
   - `lonora update` is executed by the installed script, which is main's version. Its `install_bundle` (main `infra/compose/lonora:530`) has no `retire_overlays`, and it then runs `compose up -d --wait --remove-orphans` (main `:810`) with no service list.
   - With this release's `docker-compose.prod.yml`, that `--wait` waits on `searxng` and `browser`. If the SearXNG image pull fails or either healthcheck fails, the update reaches `fail_update 'Gateway start'` and rolls back.
   - This is the exact failure the new `up_all` exists to prevent.
2. **The retired overlay stays merged until a later update.**
   - On an install whose `.env` lists `infra/research/compose.research.yml`, the old script's `install_bundle` neither removes the file from disk (it only copies bundle files) nor drops it from `LONORA_COMPOSE_OVERLAYS`.
   - The new `compose()` (`infra/compose/lonora:112-121`) keeps adding it with `-f`. Its `gateway.depends_on: {searxng: service_healthy, browser: service_healthy}` therefore stays merged.
   - So `up_all` → `compose up -d --wait ... gateway` waits on both research services at every `lonora start` and restore, until the next update after this one runs the new `retire_overlays`.

`tests/test_research_deployment.py` tests `retire_overlays` in isolation. It does not cover either path.

**Fix:**
- In `compose()`, skip any overlay listed in `RETIRED_OVERLAYS` when building `files`, so the new script never merges it, whatever `.env` says.
- In `docs/operations.md` (upgrade notes) and the PR body, state that the one update from a pre-#101 release still waits on the research services (that script is already installed and cannot be changed).
- Add a test that `compose()` drops a retired overlay.
