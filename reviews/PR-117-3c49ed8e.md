## Verified findings

### H1 (high): pressing Enter in the agent's own field approves the Trade Approval in the slot (6.10, 10.2.2)
**Where:** `apps/web/src/components/genui/UiCard.tsx:674-682`, the Number field's Enter handler:
```js
const card = event.currentTarget.closest(".ux");
const primary = card?.querySelector<HTMLButtonElement>(".btn.primary");
if (primary && !primary.disabled) primary.click();
```

**Why it reaches the trade:**
- The `Slot` node (`UiCard.tsx:525-543`) draws the live fixed card inside the agent's `.ux` card.
- The Trade Approval's Approve button is `className="btn primary sm"` (`components/trading/TradeApprovals.tsx:292`).
- The agent chooses the layout, so it can place the slot above a Number field and draw no primary Button of its own. The first `.btn.primary` in the card is then the fixed card's Approve.

**Reproduced** (Playwright, the PR's `slots` fixture plus `{"state":{"lots":0.1}}` and a Number bound to `lots`; type 0.2, press Enter):
- `POST /api/trading/approvals/<id>/decision {"decision":"approve"}`
- status `approved`

**Mandate:** a generated element approved a trade, which 6.10 forbids. The owner pressed Enter in an agent field and never tapped the fixed card. The settle card's primary button (`OwnerActionCard.tsx:446`) is reachable the same way.

**Mobile is not affected:** `primaryAt` collects only the agent's own primary Buttons (`nodes.tsx:703-709`).

**Fix:**
- Take the primary only from the agent's own nodes, e.g. `card.querySelector(".btn.primary:not(.ux-slot .btn)")`, or better, a registry of the agent's primary Button as mobile does.
- Add a web journey: a Number below a slot, press Enter, assert no `/decision` or `/resolve` request.

### M1 (medium): look-alike and invisible characters bypass the imitation check (10.2.2, "a trust frame the agent cannot imitate")
**Where:** `packages/agent-runtime/src/lonora_agent/genui_compile.py:373-376` (`_plain` = `fold` + `[^\w\s]`→space).
- It keeps no Cf filter: ZWNJ and ZWSP become a space and split the word.
- It has no confusables map.

**Probe** (`imitates_fixed_card` at the head):

| Input | Result |
|---|---|
| `'موافقة'` | True |
| `'موا‌فقة'` | **False** |
| `'رف​ض'` | **False** |
| `'Аpprove'` (Cyrillic А) | **False** |
| `'Approve'` | True |

The reviewer also compiled a full card with a Button labelled `"موا‌فقة"` through the real projector: no diagnostic.

**Fix:**
- Strip Unicode category Cf and apply NFKC plus a small Cyrillic/Greek→Latin confusables map before matching.
- Better: refuse Cf characters in agent text at contract validation.
- Add these cases to `tests/test_genui_slots.py`.

### M2 (medium): a slot counts as embedded when its message is drawn as a question or peer card, which hides the fixed card and its row (10.2.2 "never hidden", 10.2.3)
- **The count:** `embeddedSlots` (`packages/core/src/conversation-timeline.ts:9-21`) counts every assistant message whose rich content validates.
- **The renderers:**
  - Web `Conversation.tsx:979-993` passes `card={peer ? <PeerCard/> : question?.choices.length ? <QuestionCard/> : undefined}`, and `Message.tsx:371` `if (card) body = card;` draws that card *instead of* the rich content.
  - Mobile `thread.tsx:1066` does the same for a question with choices.
- **Result:** the slot's record is marked embedded, so its standalone row is suppressed, while the slot itself is never drawn.
- **The server path producing such a message** (traced in code, not run end to end): a multiple-choice question in the same turn keeps the turn's rich content (`tool_block.py:371` → `question_outcome` → `rich_metadata`), and `executor.py:179-205` stores one assistant message with both `rich_content` and `input_requests[].message_id`.
- **Fix:** apply the renderer's rule in `embeddedSlots` (skip messages drawn as a question with choices or a peer card), or draw the rich content as well. Add a timeline unit test for the case.

### L1 (low): the agent card's sent-state dims the slot
- `.ux.is-sent .ux-body { opacity: 0.82 }` (`genui.css:276`) and mobile `card.tsx:351` dim the whole body, slot included, after an owner submit. The frame then looks different (10.2.2, "never restyled").
- **Fix:** exclude `.ux-slot` from the opacity.
