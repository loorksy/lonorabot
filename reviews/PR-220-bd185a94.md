## Findings

### L1 (low): the jump mark changes the bubble's size
- Where: `apps/mobile/components/message-bubble.tsx:108-111`
- Evidence:
  - While marked, the style adds `borderWidth: 1`, and `padding: isOwner || flash ? 14 : 0`.
  - An agent message (padding 0) grows by about 30 px for 1.7 s, then shrinks, right after `scrollToIndex` placed it.
  - Web marks with a box-shadow ring and changes no size (`conversation.css` `.msg.flash`, `lists.css` "opacity only").
- Fix: keep the size constant. Draw the mark as an absolute overlay (`position: absolute`, inset 0, border, `pointerEvents: none`), or always reserve the padding and a transparent border.

### L2 (low): a second jump to the same message does not mark it
- Where: `apps/mobile/app/thread.tsx:843`
- Evidence:
  - `if (around == null || !loaded || jumped.current === around) return;` runs before the mark is set, so tapping the same quote or search hit again marks nothing.
  - Web removes and re-adds the class on every jump.
- Fix: in `jumpTo`, when `around` already equals the target's seq, call `setFlash(message.id)`.

### L3 (low): a missed call shows no visible "Tap to call back"
- Where: `apps/mobile/components/message-bubble.tsx:205-216`
- Evidence:
  - The hint is only in `accessibilityLabel={fill(t("callBack"), partLine)}`. The visible text is `partLine` alone, tinted.
  - Web shows `<Trans>Tap to call back</Trans>` under a missed call (`apps/web/src/conversation/Message.tsx:300`).
- Fix: add «اضغط لمعاودة الاتصال» / "Tap to call back" and render it under a missed call.
