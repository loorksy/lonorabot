## Findings

### M1. An order can carry no judgment label (5.5.3)
- In `packages/contracts/src/lonora_contracts/trading.py`, `label: str = Field(default="", pattern=LABEL_PATTERN)` is set on `TradeAnnotation` and on `AnnotatedTradeRequest`.
- 5.5.3 says: "Each order carries a judgment label the agent chooses". As built, a send without a label is accepted and journaled with `"label": ""`. The subagent's probe reproduced this, and the code confirms it.
- 5.5.4's per-label statistics then pool those trades under "unlabelled". The PR's deviations cover close-all having no label, but not the label being optional.
- Fix: require a non-empty label on `trade_execute` for every order. Refuse with a fixed `label_required` before anything is sent, as `reason_required` does. Either keep the requirement off risk-reducing requests (see L1), or list the optional label as a deviation for the lead to decide.

### L1. A malformed label refuses a risk-reducing close
- `LABEL_PATTERN = ^[a-z0-9_]{0,40}$` is enforced by the tool schema. So `trade_execute(action="close_position", …, label="Take Profit")` is refused whole with `tool_arguments_invalid`, and the exit is not sent until the agent retries. The subagent's probe reproduced this.
- Fix: before validating, normalise the label in `trade.execute`: lowercase it, map spaces and hyphens to `_`, and truncate to 40. Never refuse a risk-reducing request over its label.

## Rejected (one line each)
