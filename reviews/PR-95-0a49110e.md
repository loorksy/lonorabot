Web has `serverAnswered`, `flushQueued` and the same plural toast in `apps/web/src/shell/Shell.tsx:428-438` and `hooks/useThreads.ts:187,226`. Only plain owner text waits (`isPlainOutgoing`); edits, card submits and voice notes never do. The message keeps its `client_nonce`, so the server deduplicates a send the API had actually received behind a 502/504. Parity, not a new behavior.
- **"A proxy 502/504 after the API accepted the message causes a duplicate":** no. The resend carries the same `client_nonce`, which the server deduplicates. A 4xx or 503 counts as an answer and is never re-sent.
- **"Restored intents re-send by themselves after a restart":** only rows stored as `queued` and plain. A send that was in flight comes back `failed` for a manual retry (`outgoing-messages.ts` hydrate).
