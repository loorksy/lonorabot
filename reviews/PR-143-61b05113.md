## What I checked
- **Web parity:** web keeps composer drafts in `localStorage` `lonora:composer:v1:` (main `apps/web/src/lib/composer-drafts.ts:11`). Mobile does the same: `localStorage` on web, and on native a hashed file per draft key under the app's document directory.
- **Scoping and sign-out:**
  - Drafts are scoped by the draft key (server, owner, conversation), and `restoreDraft` checks `saved.key === key`.
  - Sign-out (`registerSessionTeardown`) bumps the generation, waits for pending writes, then deletes every saved draft on both platforms.
- **Never stale:**
  - `restoreDraft` fills only a draft untouched since the app started (`revision === 0`), so typing during the read wins.
  - A draft that empties is removed at once, so a restart right after Send does not bring the sent text back.
  - An oversize save clears the old file instead of leaving it.
- **Edits:** an edit's text is never saved (`markEditing`). A restart cannot turn an edit into a new message.
- **Validation and privacy:**
  - Restored data is validated: string text up to 30000 characters, at most 10 Artifact-shaped attachments, and a reply that is null or object-shaped.
  - Running uploads are never saved, and no file path or uri is stored.
