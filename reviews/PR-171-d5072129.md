## Findings

### H1. A card with no facts can still read as broker-confirmed after an unconfirmed trade (10.3, 6.4)
- **Where:** `packages/agent-runtime/src/lonora_agent/genui_compile.py:497-520`. The unconfirmed refusal fires only when a fact resolves to an unconfirmed operation, so a card that cites nothing compiles normally.
- **Why it reaches the owner:** `model_runtime.py:219-240` (`unverified_financial_result`) rewrites only confirmed-but-unverified replies. An ambiguous or submitted result keeps the agent's reply and its card.
- **Reproduced:** by the subagent's probe, and I confirmed the control flow in the code. After a `trade_execute` that returned `ambiguous`, this `summary` card compiled and was published as a `ui` part with no diagnostic:
  - title «تم تنفيذ الصفقة — أكّده الوسيط», icon `check`;
  - Badge «مؤكَّد» with tone `good`;
  - KeyValue rows «الحالة: نُفّذت بنجاح» and «الحجم: 0.10».
- **Context:** the PR title claims 10.3's sentence. Its own Deviation 1 defers this case to the 10.2.2 trust frame, but the fix does not need word matching or the frame.
- **Fix:** in `compile_card`, raise `CardError("card_fallback_unconfirmed")` when any `trade_execute` or `trade_close_positions` result in the current request is unconfirmed, whether or not the card cites it. The reply then carries text only, as `proposed & FINANCIAL_CALLS` already does for premature prose. Add a test using the card above. If the lead prefers to defer it, change the title and claim so they don't say "never".

### M1. `/results/length` counts unconfirmed operations
- **Where:** `genui_compile.py:238-242`. The `length` token turns the list into an int before `_refuse` runs, so the list's items are never checked.
- **Reproduced:** by the subagent's probe, and confirmed by reading the code. With the `TWO_RESULTS` fixture (one confirmed, one ambiguous), `{"path":"/results/length"}` compiled to `2` in a card titled "Closed". That contradicts the body's claim of "every item of a returned list".
- **Fix:** in the `length` branch, call `_refuse(item)` on every item first. Add a test.

### L1. A typed lot below 1.0 escapes the "cited, never typed" check
- **Where:** `typed_fact_numbers` (`genui_compile.py:340-363`) filters numbers with `_significant` (`:336`), which ignores non-integers below 1. A typed `0.10` after an ambiguous trade passes (probe).
- **Fix:** skip `_significant` for `TRADE_KEYS` values. H1's fix also covers this.

### L2. Stored copies outside `ln_messages` are not migrated (14.3.9)
- **Where:** `0102_genui_summary_kind.py` rewrites only `ln_messages.rich_content`.
- **What is missed:** `ln_runs.model_metadata["rich_content"]` (written at `runs.py:456`, read back by `outcome_return.py:50`), saved loop states, and `ln_events` payloads. A stored `receipt` card in any of these degrades to text, because `validated_rich_content` returns None. No data is lost.
- **Status:** code reading only.
- **Fix:** apply the same rename to `ln_runs.model_metadata`, or document these as accepted degradations.
