## Verified findings

### M1 (medium, data loss): validate/activate wipes the source directory when the draft sits where the prompt says utilities run
- `packages/agent-runtime/src/lonora_agent/skills/lifecycle.py:203-228` and `:230-246`.
- `skill_package_create` accepts `source_directory="skills/<id>/<version>"`. That is exactly the directory `materialize` clears with `rm -rf -- skills/<id>/<version>` before writing the stored copy, and the prompt (`lonora.md`: "A package's utilities run … from skills/<id>/<version>/ in your home") points the agent there.
- Everything creation leaves out is then deleted: dot-directories (`.git`, `.venv`), dot-files, `__pycache__`, and any data file not in the package.
- Reproduced: `source_directory accepted: skills/local-statistics/1.0.0 | materialize target: skills/local-statistics/1.0.0 | same: True`, and `rm -rf` of that target removes the directory with its `.git` and `notes.dat`.
- Fix: refuse a `source_directory` under `skills/` (or equal to the target) in `prepare_workspace_package`; or materialize into a staging directory and swap it in. Either way, the validate and control descriptions should say the directory is replaced.

### M2 (medium, 0.4 / 14.1.1): packages active before the upgrade have no files where their utilities are said to run
- `materialize` is called only from validate (`lifecycle.py:438`) and activate (`:501`).
- Migration 0138 fills `ln_skill_package_files`, and 3a's move copies the old snapshot to `old-workspace/skills/...`. Nothing writes `skills/<id>/<version>/` for a package that is already enabled.
- Such a package stays admitted (its stored hashes match), but the path the prompt names does not exist until the agent disables and reactivates it. The prompt line is untrue for every upgraded install.
- Fix: materialize enabled packages once (in the gateway's workspace step after `move_snapshots`, or lazily on first admission). Otherwise the prompt and docs must say that reactivating is needed.

### L1 (low): the package store is unbounded and loaded whole
- `skills/store.py` `stored_files` selects every file of every version of the agent, on each `effective_skill_registry`, the owner catalog, and validate/activate.
- The old snapshot capped the total at 8 MiB / 128 files. Now each create adds up to 1 MiB, and removal keeps the files.
- Fix: select only the paths of the entries needed (`WHERE path IN (...)`), and set a per-agent quota.

### L2 (low): validation output is not trimmed
- `lifecycle.py:473-474` returns `outcome["stdout"]` and `["stderr"]` whole (up to the supervisor's 1 MiB per stream) into the tool result and the receipt.
- `workspace_run` tails to 64 KiB (`terminal.tail`). The output is scanned, so this is about size only.
- Fix: apply `terminal.tail`, and report the omitted byte counts.

### L3 (low, docs): dot-files are skipped too, not only dot-directories
- `find … -name '.?*' -prune` (`lifecycle.py:212`) also drops `.env` or `.config.json`.
- The docstring and `docs/workspace-created-skills.md` say "dot-directories", and `tests/workspace_fake.py` copies the documented behaviour, so the tests never exercise the real filter.
- Fix: correct the text, or prune only `-type d`.

### L4 (low): migration 0138's downgrade silently loses packages created after it
- `0138_skill_package_files.py:57-58` drops the table. Packages created since then exist only there, and 0137's code then reports them as `skill_package_source_changed`.
- Fix: one docstring line stating it, or write their files back into the snapshot on downgrade.

## What I checked (with a subagent; every item above verified by me)
- **Injection and traversal:**
  - `directory` is `shlex.quote`d after `encode_snapshot` validation (no `..`, absolute paths, NUL or backslash).
  - The name and version come from validated types and are quoted; the utility command uses `shlex.join`.
  - Every supervisor operation runs as the agent's own uid, so a planted symlink reaches only what the agent could already delete.
- **Secrets:** each source file is read with `read_bytes`, which refuses any secret form. Names and bodies are scanned again before install, and listing and validation output pass the scan. No secret is injected into validation.
- **Ordinary run only:** create, validate, and activate with utilities all go through `require_ordinary`.
- **Replay:** validate is no longer `replay_safe` (tested). Create keeps its first read via the prepared receipt. Concurrent activations are decided by `expected_version`.
- **14.3.9 / 0.4:**
  - `WorkspaceSource.workspace_revision` became optional, so stored entries still validate.
  - Old `image` keys are ignored by `require_validated`.
  - The old tools are still registered at this commit.
- **Migration 0138:**
  - It is in the W-WS range, chains to 0137 and is the single head.
  - Upgrade, downgrade -1 and upgrade work.
  - A data probe copied only `skills/` entries with the right bytes.
- **Manifest:** regenerated (5.8.6); test_release_manifest passes.
