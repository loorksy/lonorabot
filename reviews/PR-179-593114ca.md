## Verified findings

### M1 (medium): the crash between create and record still loses `created`, so the orphan is billed and never removed
- `broker_provisioning.py:380` with `metaapi_provisioning.py:254-256`: on the next pass `find_or_create` finds the account and returns `(existing, False)`.
- Reproduced by a probe that makes `_record` raise once, then has the broker refuse the login:
  - `AFTER RETRY {'provisioning': 'deploying', 'created': False, …}`
  - `FINAL {'provisioning': 'failed', 'code': 'broker_login_rejected', 'created': False, 'metaapi_cleanup': None} still at MetaApi: True removes: 0`
- This was half of #141's L1; the other half (a failed removal) is fixed.
- Fix: under the provisioning lock, `find` first. If it finds nothing, persist `create_sent: true` on the card before the create; on a later pass, an account found for a card with `create_sent` counts as `created=True`.

### L1 (low): a leftover account that a later connect reuses is never removed
- The retry marks it `kept` (line ~296). The reusing card records `created=False`, so the connection gets `provisioned_by_lonora: False` (line ~546), and a later disconnect leaves it billed at MetaApi.
- Fix: when `_provision` reuses an account a `metaapi_cleanup: pending` card names, record `created=True`. Or, on `kept`, set `provisioned_by_lonora` on the connection that took it.

### L2 (low, existed before): the first removal skips the lock and the "taken" check
- `Failing.__call__` (line ~250, reached from `_deploy` ~496/500) removes without the provisioning lock or `_metaapi_account_taken`. A second gateway worker's card for the same login could have found the account meanwhile and then fails; no live connection is lost.
- Fix: route the first removal through the same locked check as `retry_cleanup`.

## What I checked
- No account in use is ever removed: the retry keeps an account that any connection or connected card uses, and defers while another card is connecting with it (tested).
- An account the owner made outside Lonora is never `created`, so it is never retried.
- The provisioning lock is held across check, remove and record, the same lock as `_provision`.
- A 404 is recorded as `not_found_with_current_token`.
- No secrets are logged, and retries are throttled by `cleanup_at`.
- tests/test_broker_connect.py and test_broker_secret_boundary.py: 20 passed.
