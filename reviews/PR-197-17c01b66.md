## What I checked
- **Webhook (6.10), a security improvement:**
  - Before, the caller's text became the run's prompt, a user-role request. Now the run's prompt is fixed server text (`SERVER_AUTHORED_TRIGGERS` gains `webhook`).
  - The caller's text (required, at most 4,000 characters, refused rather than cut) reaches the model only as the context section `webhook`, labelled `webhook_untrusted`.
  - Nothing else the caller sends (metadata, parent run, trigger) is kept: a new `RunRequest` is built.
  - The nonce receipt keeps one wake per nonce.
  - A webhook run is not an owner trigger (`OWNER_TRIGGERS` is `user`, `group`), so no owner-word tool accepts it.
  - **14.3.9:** stored webhook runs from the earlier route (caller text as their prompt, no section) are still rendered as a request in the conversation turn, never as `<wake>` server text (`wake_context`).
- **Capabilities:**
  - `not_set_up` is removed from the contract (`CapabilityState`), the labels and the tool text. Nothing in web, mobile, packages or tests references it any more.

  - The removed brave fallback is consistent with SearXNG being part of every stack, which the docs say.
