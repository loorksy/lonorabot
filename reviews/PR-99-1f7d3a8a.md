## Findings

### H1. A held run blocks the owner's card submission, and then the owner's typed words, in a paused agent's conversation (4.7.1, 3.2.5)
- Rule Q (`packages/db/src/lonora_db/runs.py:233-245`) starts a `ui_submit_origin` run only when every earlier run of its agent in the thread has ended.
- This PR adds runs that never end while the agent is paused:
  - the card-ending notice created with `held_while_paused=True` (`trade_approvals.py:277-281`);
  - queued `follow_up` and `peer` runs, which are now filtered out while the agent is paused (`runs.py:264-291`).
- It also makes a paused agent's card submission claimable (`genui_submit.py:300-304`). The result:
  1. The submission is never claimed.
  2. `messages.admit_runs` (`messages.py:521-532`) picks that stuck queued `user` run as the active run.
  3. Every typed owner message in the thread is steered into it and is stuck too, until Rule L cancels it after 30 minutes.
- So the owner cannot tell a paused agent "close gold now", a risk-reducing exit the PR says stays possible.
- Reproduced by me: `run.sh pr99 python -m pytest -q -s tests/test_pr99_probe_rule_q.py`. The probe pauses the agent, creates a `WITHDRAWN_TRIGGER` run with `held_while_paused=True`, posts the card submission (202), loops `claim_next`, then posts "close gold now".
  - Control case (no held run): the submission is claimed.
  - Held case: `claimed == []`, and the typed message's `run_ids == [stuck submission]`.
  - The probe is kept at `/tmp/claude-0/-home-user-lonorabot/e1b77bc5-dd0b-5073-a830-e13fe9447103/scratchpad/test_pr99_probe_rule_q.py`.
- Fix:
  1. Parameterise `claimable_while_paused(run=RunRow)`.
  2. In Rule Q's `behind` subquery, join `AgentRow` on `earlier.agent_id` and require `or_(AgentRow.paused.is_(False), claimable_while_paused(earlier))`, so a held run does not block a claimable one.
  3. Add to `tests/test_paused_agent.py`: a held notice, then a card submission, then a typed message; assert both are claimed or steered into a claimable run.
