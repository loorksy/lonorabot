## Finding 1 (medium): skill_restore revives a removed skill package as a plain enabled skill, skipping package validation

- File: `packages/agent-runtime/src/lonora_agent/skills/instructions.py:240-260`. `revived()` builds the row with an empty `state`, so the `package` state is dropped. `editable()` (`:128-129`) refuses only rows that carry package state.
- Effect: package hashing and the validation image are skipped (`context/skills.py:57,91` skip rows without `"package"`).
- Evidence: `tests/check_skill_packages.py` with an added step after the agent's `skill_package_control action=remove` calls `skill_restore(version=<2.0.0>, expected_version=0)`. Output:
  - `PROBE restore: {… 'version': '2.0.1', 'enabled': True, 'status': 'restored'…}`
  - `PROBE row state keys: [] enabled: True … source: external content has v2: True`
- The 2.0.0 external import is the one the same script shows refused activation (`skill_package_validation_required`). After this restore it is active as an ordinary skill. This path is new in this commit: before it, a removed package had no versions.
- Fix: record on `SkillVersionRow` whether a version came from a package. Make `revived()` refuse (`skill_package_lifecycle_required`, 409) when the last version was a package, so a removed package returns only through the package tools. Add the test.
