## Finding 1 (low): the text says the wrong thing about which mode a creation in an owner turn gets (0.4)

- Probe: Lonora is set to Full, the owner sends a message, and the run is then marked as having read external content. Output: `owner_message_id after taint: None` and `created mode: ask lonora=full`.
- The code is the safe direction. In any owner turn, a creation Lonora makes on its own judgment also starts in Ask, a conservative reading of 4.3.3, since the server cannot tell the two cases apart. The tool description and `lonora.md:503` claim otherwise.
- Fix: describe the owner-asked path as "the run answers the owner's typed message (`owner_typed_message`), also after it read third-party content". Describe the own-judgment path as "a run with no owner typed message (wake, routine, peer)". In the tool text and `lonora.md`, say that in a turn answering the owner an omitted mode starts in Ask.
