### L1 (low): the engine-as-process rule is easy to bypass, and it over-reaches into legitimate 7.1 code
- Bypassed (the test still passed): `subprocess.run(f"claude -p {…}", shell=True)`, `ENGINE = "claude"; subprocess.run([ENGINE, "-p", …])`, `["/usr/local/bin/claude", "-p", …]`, and TS `` execSync(`claude -p ${p}`) ``.
- Over-reach: the same family of patterns flags harmless code that 7.1/12.2 allows. Probes run against the test's `PATTERNS`:
  - `KNOWN_CLIS = ("claude", "codex")`;
  - a workspace test `workspace.run(["claude", "--version"])`;
  - an agent's workspace `npm install -g @anthropic-ai/claude-code`;
  - any `chatgpt.com` link;
  - a route named `/auth/setup-token`;
  - a comment mentioning `langgraph`.
- No current file trips it, but the coming workspace and "What is running" code will.
- Fix:
  - match process starts (`subprocess.*`, `create_subprocess_exec`, `spawn`/`exec*`) whose argv or command string begins with `(\S*/)?(claude|codex)\s+(-p|--print|exec)`;
  - exclude workspace-side paths, or add a reviewed allowlist;
  - narrow `chatgpt\.com` to `chatgpt\.com/(backend-api|auth|api)` and `setup-token` to `claude setup-token`;
  - match `langgraph`/`crewai` only as imports or dependencies.
