## Verified
- owner_words.submit_provenance_of(source) returns the provenance-only mark
  (ui_submit_retry_of naming the send's own Run, never ui_submit_origin) when
  `source` carries card-send provenance. retry_run and renew_approval both use it, so a
  «طلب جديد» renewal of an approval raised by a card send (or by its retry) cannot spend
  standing authority. A test asserts this:
  test_conversation_status.py::test_a_renewed_approval_keeps_a_card_sends_provenance
  checks the mark, the absence of ui_submit_origin, and `provisional_voice` being True.
- Legacy rows: on main, a card send's retry was marked `retry_of` + `ui_tainted`
  (run_retry.py:139,148). ui_submit_provenance honours `ui_tainted` only together with
  `retry_of`, so a queued retry keeps its provenance across the upgrade, while wakes and
  Tasks that release marked do not (6.10: only the run it started). On main
  renew_approval set no taint (metadata {renews_trade_approval_id} with no parent), so
  no legacy renewal loses a mark. Treating a legacy retry of a tainted wake as provisional
  is stricter, never looser.
- Docs (account-authority.md, genui.md) describe exactly this at the commit.
- Runs on fresh *_test DBs: test_genui_submit + test_conversation_status: 38 passed.
  probe_retry (main's deleted retry case, asserting provisional_voice) prints
  RETRY_MARKED True. The six core 14.1.2 files: 100 passed.
