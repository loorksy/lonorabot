## Findings

### M1. A disconnected snapshot's old figures are stamped as reconciled now (6.4, 5.3.3, 0.4)
- `packages/agent-runtime/src/lonora_agent/context/picture.py:78` sends `"observed_at": snapshot.observed_at`; the frame text (`:107-108`) tells the model the book is "from the last broker reconciliation at observed_at".
- When reconciliation fails, `packages/trading/src/lonora_trading/broker_recovery.py:113-125` writes `status="disconnected"`, `observed_at=now`, and carries over `prior.positions/orders/account`, whose real time is `last_success_at`.
- Effect: hours-old positions and floating P&L reach the model stamped with the time of the failed read, described as a reconciliation at that time. Only `"status":"disconnected"` hints otherwise. The agent may report that P&L to the owner as current (5.3.3). Reproduced by the subagent's probe: a disconnected snapshot with `last_success_at` 6 h ago rendered `observed_at` = now with the old position and `floating_pnl` 10; confirmed by reading both sites.
- Fix: in `own_book` emit `"as_of": (snapshot.last_success_at or snapshot.observed_at).isoformat()` instead of `observed_at`, plus `"stale": snapshot.status == "disconnected"` and `"reason_code"`; when disconnected with no `last_success_at`, return the `not_reconciled` shape. Frame text: "figures are from the broker at as_of; when stale is true the broker is unreachable and they may no longer be current". Add the case to `tests/check_account_picture.py`.

### M2. "Every wake" is untrue for an owner's answer to a pending question (5.4, 11.8, 0.4)
- The module docstring (`context/picture.py:3-5`) and PR body say the picture is rebuilt at every wake of a checkpointed Run.
- The owner's answer resumes the same Run with `pending_input_request` removed (`packages/db/src/lonora_db/messages.py:535-552`). In `tool_loop.py` the head is rebuilt only in the `resume_after_attention` branch (`:374-379`) and after `consume_wake` (`:405-408`); an answer is neither, and `refresh_after_steering` refreshes only skills. The agent resumes (possibly hours later) with the book frozen at Run start. Owner messages are a wake (11.8). Reproduced by the subagent's probe (a ticket opened while waiting was absent after the answer); the control flow is confirmed by reading `tool_loop.py:344-410`.
- Fix (in #92's loop, which this PR's claim depends on): before `consume_wake`, `if stale_head and await owner_steering_pending(context): await refresh_context_head(context, registry, state, messages); stale_head = False`. Add the answer case to `tests/check_account_picture.py`. If it is fixed in #92 instead, keep this docstring; otherwise narrow it.

### L1. A position with an unrecognised side counts as a sell
- `packages/trading/src/lonora_trading/picture.py:101-106` `net_volume`: anything whose `direction(side)` is not `"buy"` subtracts volume. `Position.side` is a free `str`.
- Fix: count only `"buy"` and `"sell"`; report anything else in a separate `unknown_side_volume` field.
