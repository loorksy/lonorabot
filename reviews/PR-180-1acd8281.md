## Findings

### H1 (high, 14.3.18.7 / 3.3.4) — item 7 is declared done by `ticket_agent`, which attributes netting positions to the wrong agent and forgets old tickets
- `0063_authority_migration.py:37-38`: "Positions are attributed from the journal per 3.3.4 when they are read (`ticket_agent`): nothing is written." `ticket_agent` (`packages/trading/src/lonora_trading/account_authority.py:105-138`, from 60ead1d8, earlier in the W-AUTH chain) is what the door uses for `ticket_not_owned` (`agent_permission.py:78-90`).
- (a) Netting: it walks confirmed entries newest first and returns the first whose `operation_id` matches the opener **or** whose `details.position_id` equals the ticket. On a netting account a later fill by agent B on agent A's position carries the same `positionId` (`metaapi.py:906`), so B's newer entry wins before A's opening entry is reached. 3.3.4: "On a netting account, a symbol's single position belongs to the agent whose order opened it from flat." Probe (`ticket_agent` with journal [B newer, A], position P1 with `operation_id` = A's): `netting owner: agent-B` — reproduced. Effect: A, the owner of the position, gets `ticket_not_owned` on its own close (a risk-reducing exit blocked), and B may act on A's position.
- (b) `.limit(1000)`: a ticket whose opening entry is older than the newest 1000 confirmed entries on that account and symbol is attributed to the owner (`None`); 3.3.4 gives the owner only tickets with no agent-attributed journaled opening order. Probe on a migrated DB with 1 agent-A opening entry + 1000 newer entries: owner `None`.
- `tests/check_authority_migration.py:1101-1117` covers only the hedged single-opener case.
- Fix: attribute by the opening entry — first an `operation_id` match of `target.operation_id` (the opener's client id) across all entries, then the oldest id match (`order_by(updated_at.asc())`, or the entry whose result shows it opened from flat); drop the 1000 cap in favour of an indexed lookup on operation id / position id; add netting and pending-order-fill cases. Until then, 0063's docstring and docs must not state item 7 as done.

### M1 (medium, 14.3.18.6 "done in one step") — a supervisor's pause on a paused Task aborts the whole migration
- `0063_authority_migration.py:244-257` `refuse_paused_tasks`, called at line 930 before any item is applied, raises `RuntimeError` whenever a non-Lonora supervisor's live hold targets a Task that is paused or asked to pause; `lonora update` then fails and rolls back until the owner acts in the app. The mandate says supervisor-held pauses end. The check's own case confirms the refusal is reachable. The module docstring states it; docs/supervision.md and docs/account-authority.md do not.
- Fix: end the hold as for other kinds — release it and request the resume the Task's Run state machine reads at its next checkpoint (e.g. `control_requested='resume'`) — instead of aborting; at minimum document the operator step in docs/operations.md and docs/supervision.md.

### L1 (low) — agents unpaused or flattened by 0063 emit no `agent.updated`
- `end_supervisor_pauses` sets `ln_agents.paused = false` (≈770-774) and `team_agents` changes role/parent/template/binding (624-630); `grep -c agent.updated 0063_authority_migration.py` = 0, while the live paths emit it (`supervision.py` owner_resumes / pause). A client catching up by event cursor shows stale pause/role until reload. Fix: emit `agent.updated` with the `agent_data` shape for each changed agent.

### L2 (low, section 17) — the binding line written into a flattened agent's method is English with raw ids/JSON
- `0063_authority_migration.py:613-620` writes `Assigned market, … account_id "<uuid>", broker_symbol "XAUUSD" …` into OPERATING.md, which the owner reads verbatim in the agent's memory view. Fix: name the account by its broker label (broker · login · server, as `account_facts` does) and the symbol plainly; keep the id out of owner-visible text if the agent still needs it.
