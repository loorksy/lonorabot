## Findings

### M1. A scale-in's label on a netting account is counted nowhere (5.5.3, 5.5.4)
- A closed trade carries only the label of the order that opened the position from flat (`opening_entry`, #105).
- The `management` query (`packages/trading/src/lonora_trading/statistics.py:64-77`) excludes every `ENTRY_ACTIONS` action.
- So an add to an existing netting position, labelled `scale_in` (5.2's own example), appears in neither list.
- The subagent's probe reproduced it: `n-1` was opened `breakout`, `n-2` added `scale_in`, and the close made +10. The result was `closed_trades=[{breakout, USD, 1, "10"}]` and `management: []`. The code confirms it.
- Fix: count every confirmed entry operation of the agent whose order is not a ledger row's or open position's `opening_operation_id` under its own label (count only, no money). Simplest: drop the `not_in(ENTRY_ACTIONS)` filter and exclude only operations that are some `ClosedTradeRow.opening_operation_id`. Add a netting-add test.

### M2. Unknown P&L reaches the model as `"0"` (5.5.4, 5.3.3)
- `statistics.py:28-29`: `_amount(None)` returns `"0"`. A label whose closes all lack a broker profit reports `net_realized_pnl: "0"` next to `unpriced: n`.
- Neither the tool description nor the `lonora.md` line mentions `unpriced`. The model is told it gets "the count and net realized P&L", and reads a number the broker never reported.
- The subagent's probe reproduced it: `{label: "lost", count: 1, net_realized_pnl: "0", unpriced: 1}`.
- Fix:
  - return `None` when `row.net is None`, typed `string | null` in `packages/contracts/src/performance.ts`;
  - add "closes without a broker profit are counted in unpriced and add nothing to the net" to the tool description and to the `lonora.md` line;
  - regenerate the manifest (5.8.6);
  - add an all-unpriced test.
