## Verified findings

### M1 (medium): mobile offers Retry on runs the server always refuses, and can hide the owner's real failed reply
- **Where:** `packages/core/src/run-state.ts:39-49` (`retryableFailure`, new in this PR), used at `apps/mobile/app/thread.tsx:883-887` and `:1004-1008`.
- **What it does:** it takes the thread's newest run of any kind. It applies no trigger or `parent_run_id` filter.
- **What web and the server do:**
  - Web offers Retry only for `["user","group"]` runs with no `parent_run_id` (`apps/web/src/lib/failed-replies.ts:9`).
  - The server refuses everything else with 409 `run_not_retryable` (`packages/db/src/lonora_db/run_retry.py:28,99-100`).
- **Probe** (`tsx` against the head's core, rate-limit error code, time past Retry-After):
  - a failed `routine` run gives `retryableFailure` = `r` (Retry is offered);
  - a failed run with `parent_run_id` gives `s` (Retry is offered);
  - a failed `user` run followed by a newer succeeded `routine` run gives `null`: the owner's retryable reply loses its Retry.
- **Effect:** a Retry button that always ends in an error, and a real failed reply without Retry. Nothing runs twice; the server stays authoritative.
- The comment at `thread.tsx:883` ("as on Web's error card") is untrue at this commit (0.4).
- **Clause:** 13.1 (parity with web and the server), 0.4.
- **Fix:**
  - Filter `runs` to `["user","group"].includes(run.trigger) && !run.parent_run_id` before choosing the newest, as `failedReplies` does.
  - Add unit cases for a routine run, a subagent run, and a newer unrelated run.
  - Add a routine or subagent fixture to `tests/mobile/message-actions.spec.mjs:227`, which today mocks only `trigger:"user"`.
  - Correct the comment.

### L1 (low): the banner no longer shows a non-retryable failed run
- **Where:** `apps/mobile/app/thread.tsx:1004-1008`.
- **What changed:** main's filter `run.status === "failed"` became `run.status === "failed" && retry?.run.id === run.id`. An "other"-family failure (for example `execution_uncertain`) or an older failure no longer gets the banner line.
- **PR body:** says "What was removed: Nothing".
- **Fix:** keep the failed-run status line in the banner and gate only the Retry button on `retry`, or list the removal in the PR body.

### L2 (low): "Turn into a task" is stricter than web, and the PR claims parity
- **Mobile:** `apps/mobile/lib/message-actions.ts` `canTurnIntoTask` excludes any message with `attachment_ids` and any non-text rich part.
- **Web:** `apps/web/src/conversation/Conversation.tsx:534-536` (main) excludes only GenUI and voice. A text message with files can become a task on web but not on mobile.
- **Fix:** use web's predicate (`!hasGenUi && !voicePart`), or record the deviation.
