## Verified findings

### M1 (medium, broken test after the merge): #103's broker-boundary guard fails at c88cc70c
- The merge commit changed `save_broker` (`apps/api/src/lonora_api/routes/secret_cards.py`) to construct `BrokerSecrets(rt.db, …)` itself.
- `tests/test_broker_secret_boundary.py::test_only_the_broker_layer_constructs_the_broker_reader` pins the files allowed to hold the reader.
- Reproduced: `AssertionError … tests/test_broker_secret_boundary.py:38` (1 failed, 2 passed).
- The behaviour is right; only the boundary list is stale.
- Fix: preferably let `lonora_trading.connections` build `BrokerSecrets` from `(db, key, owner_id)` so route code never holds the reader. Or add the route to `BROKER_READERS` and update the `broker_secrets.py` docstring.

### L1 (low, 0.4): a doc added in the merge describes injection that is not built
- `docs/trusted-sources.md` (~270-275, new in c88cc70c): "a workspace command given that secret can call the server directly". At this commit nothing puts workspace secrets into a command (`/run/secrets` or env); that lands with #122.
- Fix: word it for when injection lands, or drop it until then.

### L2 (low, 17): the tool never asks for owner-language labels
- An agent's own Secret card shows the agent's `label` and field labels verbatim. Only a Python comment says "in the owner's language"; the `owner_action_propose` description the model reads does not.
- Fix: add "label and field labels in the owner's language" to the description, then regenerate the manifest.

### L3 (low, 6.10 design): a tainted run or a peer can raise the agent's own Secret card
- `propose_card` (`tools/owner_actions.py:~266`) applies no `owner_message_id` or taint check for `kind="secret"`. A run that read a page, feed or peer message can show a card titled, for example, "MetaApi token".
- The value lands in workspace scope only (7.2.3 holds), and 7.2.1 does not require an owner message. It is a phishing path once injection lands.
- Suggest: for the agent's own cards when `owner_message_id(...) is None`, either refuse, or add a fixed card line saying the request followed outside content.

### L4 (low, 7.2.6): a keyed feed can echo its key into item links
- `safe_link` (`adapters/market/news_feed.py:49`) drops only links equal to the feed's own scheme, host and path.
- `https://host/article/3?apikey=K` reaches `news_feed_read` output, and value redaction misses `K` because the stored secret is the whole URL.
- Fix: drop or strip the query of links on the feed's host that share a query value with the feed URL.

### L5 (low, 0.4): migration 0071's docstring says "the agent asks again on its next run"
- Pending `connect_credential` rows become `expired`/`card_kind_removed`, and nothing wakes or tells the agent.
- Fix: reword it ("is settled; the agent can ask again"), or wake the agent with fixed text.

### L6 (low): the owner-actions lock is held across MetaApi calls
- `connect_account` (`trading/connections.py:56-78`): `within` takes `lock_owner_actions`, then the same transaction may call `verified_identity` on older connections. Every card of the owner waits on MetaApi.
- Fix: run `within` after the identity backfill, just before the writes.
