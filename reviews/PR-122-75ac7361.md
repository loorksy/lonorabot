## Verified findings

### M1 (medium, 7.2.6): wrapped base64 or hex forms leak at a cut or EOF
- `client.py` `trailing()` (~58-75) compares the raw tail with `form.startswith(piece)` without removing line breaks, while the scan's `Squeezed` does remove them.
- A stream or file ending after a line break inside a wrapped form shows the earlier complete lines.
- Reproduced with a 63-character value cut at every position:
  - base64 wrapped at 76 columns: 83 encoded characters visible (`'…\ncHJlZml4czNjcjN0LVZhbHVlLTAxMjM0NTY3ODlhYmNkZWZYWVotYW5kLXNvbWUtbW9yZS1jaGFy\ncy0wOTg3NjU0MzI'`);
  - hex wrapped at 60 columns: 89 hex characters, about 44 bytes of the value.
- Reachable through `workspace_file_read` of a killed background `base64`/`xxd -p` log, and the reader-cancel path. The timeout path is safe because of the margin trim.
- Fix: run `trailing` on the newline-squeezed text and map back with `Squeezed.span`, or drop from the start of the last run of base64/hex-alphabet lines at a cut or EOF.

### M2 (medium, 7.2.6): a rotated or deleted value is unguarded once its job ends
- `release()` drops a finished job's values from `guard`. The job's log still holds the old value, and the Gateway scans only current values. Reading the log after the job ended returned `old=s3cr3t-Value-0123456789abcdefXYZ`.
- Children that outlive the job (setsid, double fork) keep the old env unguarded; the probe's daemon wrote `late=s3cr3t-…`.
- After a supervisor restart, `job_secrets` is empty.
- Fix: keep released values in the guard while any marked process of the job lives and while its log file exists (persist them encrypted or in root-only tmpfs so a restart keeps them). Or have the Gateway keep recently rotated or deleted values in its scan for a bounded time.

### M3 (medium): a refcount race deletes a secret file a just-started job named
- `supervisor.py` `start()` (~424-463): `place_secrets()` runs before `await create_subprocess_exec`, but `job_secrets[job_id]` is registered only after it. A job naming the same secret that ends in that window unlinks the file.
- Reproduced: B found `/run/secrets/K` missing in 3 of 150 runs (9 of 150 in a second run), while its env still had K.
- In the same family:
  - a failed spawn leaves a placed file with no holder;
  - a background job whose main process exits while its children keep running loses the file.
- Fix: register the holder before `place_secrets`, remove it on spawn failure, and do place and release under `self.lock`. Release when the job's last marked process ends.

### M4 (medium, correctness): the guard changes byte lengths in file reads
- `supervisor.py` `read_file` (~593-597) runs `guard()` over the returned slice, margins included. The bytes get shorter, but the client computes `before`, `limit` and `at_end` from the original offsets.
- Reproduced: a file of `a*10 + V + "HELLO-WORLD-BODY"`, read at offset 42 (exactly the body) while a job holding V ran, returned `''`.
- The decode/encode with "replace" also rewrites non-UTF-8 bytes of binary files when a match occurs.
- Fix: return the raw bytes plus the spans of guarded values (or the values themselves, to be scanned on the Gateway side), and let the client redact after windowing.

### L1 (low): trailing-rule false positives
- With `PARTIAL=6`, ordinary output endings are redacted when a value begins with common text. Reproduced:
  - `'see file: -----BEGIN'` → `'see file: [secret:PEM]'`;
  - `'export SK=sk-proj-'` → `'export SK=[secret:SK]'`;
  - `'hex 2d2d2d2d2d'` → `'hex [secret:PEM]'`.
- This only over-redacts; no leak.
- Fix: a minimum of about 8 characters, or require the match to cover more than a shared prefix (for example 25% of the form).

### L2 (low): two statuses still map to "unavailable"
- `client.py` ~122 maps every status except 200/422/503 to `workspace_unavailable`. A supervisor 500 raised after `create_subprocess_exec`, and the new 499 `workspace_caller_gone`, should map to `workspace_outcome_unknown`.
