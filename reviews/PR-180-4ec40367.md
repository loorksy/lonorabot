## Findings
- **M2 (medium) packages/db/migrations/versions/0063_authority_migration.py:925.** A paused
  Task whose Run has ended is released with no wake and left stalled. The case is a
  Task with status "paused" whose newest Run in its conversation is cancelled or
  failed, with no "failure" recorded on the Task: live is None, return False. The hold
  is released, the Task stays paused, and no Run is queued. Live control_task would
  refuse to resume it (task_run_not_found), which is exactly the silent stall the
  agreed M1 contract forbids ("otherwise release the hold and send one fixed-text
  wake"). The same applies to the final else: return False when the Run is not live.
  Reproduced by scratchpad/repro/repro_stall.py: for both the cancelled and the failed
  case the output was "hold released: True, task status: paused, runs in thread: 1".
  Fix: when the Task is paused and has no live Run, return True so the agent is woken,
  or withdraw the pause so its own resume works (W-AUTH's announced round 3). Add both
  cases to check_authority_migration.
- **L1 (low) 0063:902-907 against the docstring at 0063:54-55.** A hold on work that is no
  longer paused still gets a wake. The failure branch returns True for a Task with
  status "failed", or waiting_reason "retry_backoff", that has a "failure", before any
  paused check. Live work_paused() says such work is not paused, and the docstring says
  "work no longer paused are only released". Reproduced by repro_unpaused.py: live
  work_paused is False, yet an owner_card Run is queued. Fix: return True only when
  the work is paused, or correct the docstring. W-AUTH's round 3 says "a stale hold on
  unpaused work gets no wake", which matches.
- **M1 (medium, inherited from #74 c07ec112):** check_risk_limits fails with
  tolerance_required. See PR-74-c07ec112.md.
