## Verified findings

### L1 (low, availability inside the workspace): the per-uid DNS rate limit does not isolate agents
- `netguard.py` `Rate`/`udp_uid` finds the sender in `/proc/net/udp` by `127.0.0.1:port`. An unconnected UDP socket is listed as `00000000:port`, so its uid is `None`, and all such senders share one 200/s bucket. The check runs in userspace after the packet is queued, with a full `/proc/net/udp` read per datagram. DNS over TCP has no limit.
- Reproduced. Victim uid 20001 makes one lookup per 50 ms (baseline 233/233 answered). Under a flood from uid 20000:

  | Flood from uid 20000 | Victim answered |
  |---|---|
  | unconnected, ~300 q/s | 7/13 |
  | unconnected, full speed | 0/6 |
  | connected flooder in its own bucket | 0/6 |
  | burner sockets | 0/6 |

  The service recovers when the flood stops. Lonora's own services are not affected.
- Fix: limit in the kernel, for example `meta skuid != 0 udp dport 53 meter dns4 { meta skuid limit rate 200/second burst 50 packets } accept` then drop, and the same for TCP 53.

### L2 (low, availability inside the workspace): an agent can add a shared address to the block list
- `Answers.lookup` adds every address in an answer to `denied` when any name in it is denied, and `dns.names` also scans the authority and additional sections.
- Reproduced with a fake resolver:
  - `poison.example` → CNAME `zz.agiliumtrade.ai` → A 45.33.1.1;
  - `poison-auth.example` with an additional-section record owned by `ns1.agiliumtrade.ai`.
  - Afterwards `pypi.test` (45.33.1.1) and `shared4.test` (45.33.1.4) are refused for every agent until the guard restarts, because `learned` only grows.
- How realistic this is depends on what the upstream passes through. A real recursive resolver re-resolves an out-of-zone CNAME target itself. An agent-owned CNAME to a MetaApi subdomain hosted on shared CDN space would also do it.
- Fix: take addresses only from answer-section records whose owner name is under a denied domain, ignore the authority and additional sections, and expire or cap denied entries (logging them).
