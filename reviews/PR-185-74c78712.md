## Finding 1 (medium, 6.9): an observe-only broker wake of Lonora can delete a team agent

- `agent_control` is non-financial and `replay_safe` (`packages/tools/src/lonora_tools/supervision.py:695-712`). `Tool.permitted("observe_only")` allows every non-financial tool (`base.py:95-100`), and `lead_control` does not check the run's scope (`supervision.py:500-505`).
- Probe at this head (run by me): a Lonora run with trigger broker_event and `authority: observe_only` (the owner's-manual-activity wake, "no financial effects") calls `agent_control delete`. Output: `OBS delete result: {'deleted': True, 'changed': True}` and `OBS agent gone: True`.
- A wake about activity Lonora did not cause can therefore make an irreversible change that moves ticket ownership to Lonora and withdraws the agent's cards. `cancel_run` and `set_ask` already behaved this way, and delete extends it to an irreversible action.
- Fix: in `lead_control` (at least for `delete`), refuse when `run_scope(run.trigger, run.model_metadata) != "full"` (`observe_only_execution_forbidden`), and add a test.

## Finding 2 (low): a replayed delete reports failure although it happened

`agent_control` is replay-safe through the handler receipt. A crash after the commit but before the result is stored makes the replay call `owned_agent`, which raises `agent_not_found` (probe P6: `second delete: agent_not_found`), so Lonora is told the delete failed. Answer a replayed delete of a missing agent with `{"deleted": True, "changed": False}`, or mark delete `reconcile_required`.

## Finding 4 (low): the wake's ticket list and the door's ownership use different windows
