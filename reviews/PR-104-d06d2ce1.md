## Status of the findings from a3e4d4b4
- **L1** (one agent could starve another's DNS): **fixed.** The userspace `Rate`/`udp_uid` is gone. DNS is now metered in the kernel per agent uid, over UDP and TCP:
  `set dnsrate { type uid; flags dynamic; timeout 1m; size 4096; }` and `oifname "lo" meta skuid != 0 meta l4proto { tcp, udp } th dport 53 update @dnsrate { meta skuid limit rate over 200/second burst 50 packets } drop`.
  The generated ruleset loads (`nft -c` in a scratch netns). The flood probe was not re-run; the meter is keyed by the socket's own uid, so unconnected sockets no longer share one bucket.
- **L2** (a shared address could be blocked for everyone): **fixed.**
  - `dns.names` reads the answer section only.
  - The block list takes only A/AAAA records whose owner name is itself under a denied domain (`dns.owned_addresses`). A shared address that a CNAME chain merely passes through stays reachable.
  - Entries expire after 24 h and are capped at 4096.
  - A record owned by a denied name is MetaApi's own (with a real recursive resolver), so blocking it is intended.
