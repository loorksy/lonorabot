## Verified findings

### H1 (high): concurrent workspace calls kill each other; a command that ran is reported as not run
- `packages/workspace/src/lonora_workspace/client.py:68,77-83`: one `httpx.AsyncHTTPTransport` per client, and every call does `async with httpx.AsyncClient(transport=self.transport, …)`. Closing an `AsyncClient` closes the transport it was given.
- `gateway/runtime.py:23` `WORKSPACE = Workspace()` is shared by every agent's run.
- So any short call that ends (another agent's `workspace_processes`, a file read) tears down every request in flight, including a 10-minute `workspace_run`.
- Reproduced with the real `WorkspaceClient` against a fake supervisor on a Unix socket: a 2 s `/v1/run` with a `/v1/processes` call at 0.5 s gave `["LonoraError('workspace_unavailable')", {'processes': [], 'jobs': []}]`. The command completed on the supervisor.
- The model is told the workspace was unavailable for a command that ran, which invites running a non-idempotent command again.
- Fix: one long-lived `httpx.AsyncClient` per `WorkspaceClient`, closed on shutdown. Or build the transport inside `_call`. Add a test with two concurrent calls.

### H2 (high, secret leak, 7.2.6): output cut at a timeout returns most of a secret in clear
- `client.py` `cut_output` (~50-60) trims the `MARGIN` tail only when `*_dropped_bytes > 0`.
- A stream can also end inside a value with nothing dropped. Examples:
  - a timed-out command is SIGKILLed mid-buffer (`supervisor.py` `foreground` ~404-447);
  - a reader is cancelled while a child still holds the pipe.
- The scanner cannot match a partial value.
- Reproduced with the real supervisor (as root): `perl -e 'while(1){print "x" x N . "token=$ENV{API_KEY}\n"; …}'` with `timeout_seconds=1`. After `cut_output` and the scan, 6 of 12 runs ended in clear text, e.g. `…token=s3cr3t-Value-0123456789ab` (24 of 32 characters), with `timed_out=True` and `stdout_dropped_bytes=0`.
- This is an ordinary program, not a transform 7.2.6 accepts. The same holds for a file whose writer was killed mid-value: `read_text` at EOF shows the prefix.
- Fix:
  - Treat `timed_out` or a cancelled reader as a cut stream (trim `MARGIN` and count it).
  - Also give `SecretScan` a trailing-partial rule: a suffix of the text that is a prefix (≥6 characters) of any form of any value becomes `[secret:NAME]`. Apply it to stdout/stderr and to file reads that reach EOF.

### H3 (high, secret leak; narrow precondition): a read offset inside a multibyte character exposes a non-ASCII secret
- `client.py` `read_text` (~143-146) decodes head, body and tail separately with `errors="replace"`. An `offset` or `offset+limit` inside a UTF-8 character turns it into U+FFFD, and the value no longer matches.
- Reproduced with the secret `ключ-секрет-абвгд-12345`:
  - offset 101 gave `'�люч-секрет-абвгд-12345BBB…'`;
  - limit edge 112 gave `'…ключ-с�'`.
- ASCII values were edge-safe in every encoded form tried.
- Fix: decode once, map the byte bounds to character indices (or move them to UTF-8 character starts), then window the single decoded text.

### H4 (high, secret leak): a rotated or deleted secret's old value stays in `/run/secrets/NAME` and comes back unredacted
- `supervisor.py` `place_secrets` / `drop_secrets` / `start()` (~319-358):
  - a file is rewritten only when a command names the secret again;
  - files are dropped only on the next `workspace_run` (only it sends `current_secrets`).
- Reproduced with the real supervisor:
  - **rotated:** agent B reading the file returned the full old value, because the scan holds only the new one;
  - **deleted:** `workspace_file_read` (also allowed in helper and observe-only runs) returned the value with an empty scan.
- Background processes keep old values in their environment as well.
- Fix:
  - A secret file exists only while a command that names it runs (refcount per name; remove it when the last such job ends).
  - At minimum, `/v1/files/read` and every run delete the files of names the request does not supply.
  - Keep recently rotated or deleted values in the scan for as long as any process started with them is alive.

### M1 (medium): errors after the request was sent are reported as "workspace_unavailable"
- `client.py:82`: `except httpx.TransportError` also catches `ReadTimeout`, `ReadError` and `RemoteProtocolError`, which occur after the command reached the supervisor. "Nothing ran" and "outcome unknown" share one code.
- Fix: map `ConnectError`/`ConnectTimeout` (and a missing socket) to `workspace_unavailable`, and everything else to a distinct `workspace_outcome_unknown` whose text tells the model to check `workspace_processes` instead of re-running.

### M2 (medium): cancelling a run does not stop its foreground command
- When the Gateway task is cancelled (run cancelled, Gateway shutdown), the HTTP request is dropped. Starlette does not cancel the handler, and `foreground` (`supervisor.py:404`) never checks for a disconnect, so the command runs to its 600 s limit.
- Partly reproduced: with the client cancelled at 0.5 s, the handler still completed.
- Fix: on `CancelledError` the client calls `/v1/processes/stop` for that job. Or `foreground` races the command against `request.is_disconnected()` and `killpg`s.

### M3 (medium, 0.4): code and text for the CLI identity that does not exist at this commit
- `packages/tools/src/lonora_tools/context.py:39-42` adds `agent_token` ("once the CLI exists"). No `ToolContext(` sets it (`runtime.py:98`), so the client and supervisor token fields are always empty.
- `terminal.py:73-93`: the docstrings of `ordinary_run`/`require_ordinary` justify refusing commands to helpers and observe-only wakes because they "could … trade through `lonora`". That command does not exist yet.
- The `workspace_run` description says secret values "never appear in output". That is untrue: 7.2.6 accepts that a transform can defeat the scan, and see H2-H4.
- Forward note: once tokens exist, the scan includes only the calling agent's token. It must include every agent's token of the owner, or agent A could read B's token from shared files unredacted (7.3.3).
- Fix:
  - Land the token plumbing (context field, client and supervisor fields, `PROTECTED_ENV` entry, scan lines) with the CLI in 7.3.
  - Ground `require_ordinary`'s docstring in today's behavior (6.9 run integrity), or drop it until then.
  - Word the tool description as "are replaced by `[secret:NAME]` in output".

### L1 (low): a failed secret write leaves a readable temp file
- `place_secrets` leaves `.NAME.<hex>` behind if `os.write`/`fchown` fails (for example ENOSPC on the 4 MiB tmpfs), and `drop_secrets` skips dotfiles.
- Reproduced: `.API_KEY.deadbeef` survived a run with `current_secrets=[]`.
- Fix: `os.unlink(temporary)` in an except branch, and let `drop_secrets` remove stale dotfiles.

### L2 (low): injection and scan come from two reads of the store
- `terminal.py` `run()` (~98-112) reads `workspace_values()` for injection, then again inside `scan()`. A rotation in between injects the old value and scans for the new one.
- Fix: build the `SecretScan` from the same `values` dict.

## Rejected
- Every agent can read every placed secret file: matches 7.2.4 ("any agent may use any workspace secret by name").
- Name traversal: names are `^[A-Z][A-Z0-9_]{0,63}$` in the tool, the supervisor and the store.
