## Findings

### H1. A grant's account gets no task, and a stored grant task runs beside the Full-mode task (0.4, 14.1.1, 4.5.1)
- **What changed.** `finish_activation` no longer creates the grant's task (`packages/auth/src/lonora_auth/account_authority.py`). `ensure_management_task` no longer yields to a driving grant task (the `grant_task_drives` precedence is removed in `packages/db/src/lonora_db/management_task.py`). The revoke hand-over is removed.
- **Why it matters at this base.**
  - `finish_activation` is still reachable from `routes/account_authority.py:134` and `routes/owner_actions.py:620`. A newly signed full grant now starts no work, so the grant feature stops working before W-AUTH deletes it.
  - Per-grant task rows already stored (keyed `stable_id(grant, "account-management-task")`) carry no `MARKER`, so `live_management_task` does not see them. A Full tap then starts a second management task for the same agent.
  - A Full agent whose mode task was held back by a grant used to get it back on revocation through the hand-over. That hand-over is gone, so it now gets nothing.
- **Reproduced by me.** `run.sh pr162 python /home/user/wt/probes/pr162_legacy_probe.py` prints `mode task live: queued` and `queued management runs: ['grant', 'mode']`. The same probe on #80 prints `mode task live: False` and `['grant']`.
- **Fix.** Rebase onto W-AUTH step 9 (0063) at least, and preferably step 10. Until then, keep `grant_task_drives` and the revoke hand-over. Alternatively, have `ensure_management_task` first close any live legacy grant task of the agent.

### M1. The grant binding of a grant task's Run is removed while grants still exist (0.4, 14.1.3)
- **What was removed.** In `packages/trading/src/lonora_trading/account_authority.py`:
  - the `available_authority` branch that held a grant management Run to its own grant envelope;
  - `require_account_execution`'s `account_authority_scope_mismatch` refusal.
- **Effect.** A still-live legacy grant-task Run (see H1) whose grant was revoked or replaced falls through to the general query and can spend another active grant of the same agent.
- **The test that guarded this is also removed**: the "old management task spent replacement authority" block in `tests/check_full_account_management.py`. That assertion belongs to the grant feature, which 14.1.3 allows removing only in the change that removes grants.
- **Status.** Confirmed by reading the diff; not executed.
- **Fix.** Keep both checks, and the test, until grants are deleted or 0063 is in the base.

### M2. The gold-journey J1 count hides an owner action (14.1.3)
- **Where.** `tests/check_simple_lonora.py:727-741`.
- **What happens.** After the passkey grant card, the test calls `set_trading_mode(..., by="owner_tap")` directly on the database. That skips the Mandate card and the confirmation counter, and `self.journey(name, 1)` still asserts one confirmation.
- **Why that is wrong at this commit.** J1 really needs two owner actions: the grant signature, then a Mandate tap. Nothing in the J1 flow raises the Mandate card.
- **Fix.** Drive the tap through the owner-action route and expect 2. After W-AUTH step 10, J1 becomes the Mandate card alone, with a count of 1.
