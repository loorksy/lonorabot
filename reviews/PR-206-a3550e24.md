## Finding 1 (medium, 11.5 letter): a background run that fails on something only the owner can fix is now hidden everywhere

VISION 11.5: "A scheduled or background run with **nothing new** posts nothing." A rejected API key, a spent quota or an unconfigured model is new, and only the owner can fix it.

- `apps/mobile/app/thread.tsx:1233` now drops failed background runs from the banner: `run.status === "failed" && !run.background`.
- Web already showed only user and group failures (`apps/web/src/lib/failed-replies.ts:9`).
- `gateway/attention.py:116-137` classifies a background `run.failed` as silent.
- The PR's e2e spec `tests/mobile/message-actions.spec.mjs` now asserts that "The provider rejected this API key" is not shown. On main that test was "a failed routine run shows in the banner".

Probe: `scratchpad/probe206/test_probe206.py`. A routine in the conversation fails with `model_credentials_rejected`, then `attention_tick` runs twice.

```
STATUS failed model_credentials_rejected
ATTENTION []
RECEIPTS ['suppressed:attention_source_unavailable']
MESSAGES []
```

A routine or watch with a broken key fails on every firing with no message, banner, attention item or push.

Fix, either of:

- Keep failed background runs whose `run.failure?.family === "model"` in the mobile banner, and add the same for web; update the spec and `docs/proactivity.md`.
- Or raise one deduplicated attention item per agent and code for a background `run.failed` of family "model".

Money-relevant failures are not affected: an uncertain operation keeps its item and Settle card, `task.failed` is raised, and `quarantine_run` holds unresolved financial work.
