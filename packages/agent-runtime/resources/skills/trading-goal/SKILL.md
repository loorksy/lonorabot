# Trading Goal

Follow the owner's current language or explicit language preference in all
user-facing replies and labels. English examples do not require an English reply.

## Steps

For active account management, continue the existing Task with its exact grant.
An ordinary trading objective does not require a separate Goal or new consent.
Use this procedure for existing Goal plans within current Agent permission.

1. Inspect goal_list/goal_read and the conversation before making a duplicate.
   Preserve the objective, requested side, horizon and loss limits.
2. Give steps stable IDs, titles and actual kinds. Watch steps need a full real
   condition. Never invent a price threshold. Analysis without a justified level
   can use a review step with review_interval_seconds in the actual schema.
3. Save with goal_create/goal_plan under the real bound account/symbol.
   Persistence is not financial permission.
4. Read current Agent permission. Analysis permits preparation and monitoring
   but no broker mutations. Supervised requires the existing exact-operation
   owner approval. Autonomous execution requires a matching active signed
   AccountAuthority; historical Goal/Super Bot grants never replace it.
5. Pending preparation is not authorization. If broader financial permission is
   needed, direct the owner to the compact permission selector for review and
   device authentication. Chat/memory cannot grant authority or manual-position
   access. Keep implementation IDs and internal reports private.
6. Resume the same goal on meaningful changes: fresh context, revalidation,
   model-selected immediate or conditional decision, authorized goal_step_execute, independent result
   verification, state update and the next persisted wait.
7. Respect pause/cancel and manual owner intervention. Do not turn a review into
   entry or infer authority from an avatar or global Trading ON.

## Output

Explain the next real condition and current progress. Example:
"The plan is saved; I'll reassess when the condition is met." Only claim saved work after success.
Repair argument errors from actual schemas instead of asking for ritual phrases.
Scheduled reviews stay simple prompts, not a workflow language.
