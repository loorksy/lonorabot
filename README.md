# Lonora

نظام وكلاء ذكاء اصطناعي دائمين، بخادم Python وواجهة Web مستمدة من قالب Tampletgrok، وتطبيق Expo مرافق. المحادثة هي مساحة العمل: قائمة الوكلاء والمجموعات، محادثة مستمرة لكل وكيل، ولوحة سياق للهوية والمعرفة والعمل المجدول. تشغيل الوكلاء يبقى على الخادم عند إغلاق المتصفح أو الهاتف.

خطة النقل ومصادر المكونات ومعايير القبول في [docs/UI_MIGRATION_PLAN.md](docs/UI_MIGRATION_PLAN.md). إشعارات المصادر والتراخيص في [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).

## التشغيل المحلي

المتطلبات: Python 3.12، Node.js 22.22 أو أحدث، pnpm 11.25.0، وDocker مع Compose.

```sh
bash scripts/install.sh
bash scripts/dev.sh
```

التثبيت يحفظ إعدادات `.env` الموجودة ويولد مفاتيح الإعداد والتشفير وLiveKit الناقصة محليًا. يبدأ أمر التطوير PostgreSQL وLiveKit، يطبق الترحيلات، ويشغل FastAPI والواجهة المبنية على المنفذ 8000 والعامل المقيم. افتح واجهة الخادم، وأنشئ حساب المالك باستخدام `LONORA_BOOTSTRAP_TOKEN` الموجود في ملف `.env` الخاص. لا توجد كلمات مرور افتراضية أو تسجيل عام.

```sh
curl -fsS http://127.0.0.1:8000/health
curl -fsS http://127.0.0.1:8000/ready
```

تتحقق الجاهزية من قاعدة البيانات ونبض العامل المقيم. سجلات التشغيل في `.runtime/api.log` و`.runtime/gateway.log`. لتعديل Web مع التحديث الفوري شغل `pnpm --filter @lonora/web dev` بجانب الخادم؛ الوكيل لا ينفذ داخل Vite.

## توصيل النماذج والصوت والتداول

افتح إعدادات النظام لإضافة مفاتيح المزودين إلى مخزن الخادم المشفر، واكتشاف الكتالوج الرسمي، واختيار التوجيه العالمي. المزودون المعتمدون: OpenAI وAnthropic وDeepSeek وZ.ai وOpenRouter. إنشاء الوكيل يحتاج الاسم والصورة واللون فقط؛ تعليماته مستقلة، وإعداد النماذج عالمي.

الصوت يستخدم LiveKit ونفس المحادثة ومنطق التنفيذ، ويتطلب مساري STT وTTS عالميين صالحين. يتطلب التداول حساب MetaApi فعليًا أو بيانات محاكاة مستوردة صراحة. ضوابط OFF/ON والإيقاف الطارئ وسجل العمليات والمصالحة تُطبق على الخادم. لا يتضمن المشروع مفاتيح مزود أو حساب وسيط أو بيانات أسعار افتراضية.

## تطبيق Expo

```sh
pnpm dev:mobile
pnpm check:mobile
pnpm build:mobile
```

العميل يحتوي قائمة الوكلاء والمجموعات، الإنشاء، المحادثات والمرفقات، حالات التنفيذ والإلغاء والاستعادة، وملخص الإعدادات العالمية والاستخدام. أدخل عنوان خادم يمكن للهاتف الوصول إليه بعد إنشاء حساب المالك عبر Web. جلسة Native محفوظة في SecureStore وقابلة للإبطال من الخادم؛ نسخة Expo Web تستخدم Cookies وCSRF.

`build:mobile` يصدر حزم JavaScript لـ Web وiOS وAndroid. إصدار تطبيق أصلي يتطلب Android SDK أو Xcode وجهازًا أو محاكيًا والتوقيع الخاص بك. السوق والصوت ولوحات المهام وتعديل المعرفة وإدارة الاتصالات متاحة حاليًا في واجهة Web الكاملة. التفاصيل والحدود في [apps/mobile/README.md](apps/mobile/README.md).

## التحقق والنشر

```sh
bash scripts/build.sh
bash scripts/migrate.sh
```

يشمل البناء Ruff وPyright وBiome وأنواع حزم Web/Expo وبناء Web وتصدير Expo للمنصات الثلاث. اختبارات CI الوظيفية تستخدم PostgreSQL ونماذج اختبار صريحة، وليست دليلًا على اتصال حسابات مزود أو وسيط حقيقية.

ملفات الإنتاج في `infra/compose/docker-compose.prod.yml`. بعد ضبط المجال العام وعنوان RTC وكلمات المرور والمفاتيح الخاصة:

```sh
bash infra/compose/deploy-main.sh --build
```

وضع `--build` يبني صورة الخادم من المصدر. وضع `--pull` يستخدم صورة السجل. صور الخادم تشمل Web وPython؛ حزم تطبيق الموبايل تُبنى بصورة مستقلة. يحتفظ مسار النشر بالنسخ الاحتياطية للبيانات والمرفقات ومفتاح التشفير؛ احفظها في موضع خاص. لا تشغل أدوات تقوية المضيف على بيئة التطوير السحابية.
