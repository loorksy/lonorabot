# Lonora

نظام وكلاء تداول بالذكاء الاصطناعي دائمين، بخادم Python وواجهة Web مستمدة من قالب Tampletgrok، وتطبيق Expo مرافق. المحادثة هي مساحة العمل: قائمة الوكلاء والمجموعات، محادثة مستمرة لكل وكيل، ولوحة سياق للهوية والمعرفة والعمل المجدول. تشغيل الوكلاء يبقى على الخادم عند إغلاق المتصفح أو الهاتف.

بنية الملفات ووظائفها في [docs/FRONTEND_STRUCTURE.md](docs/FRONTEND_STRUCTURE.md). خطة النقل ومصادر المكونات ومعايير القبول في [docs/UI_MIGRATION_PLAN.md](docs/UI_MIGRATION_PLAN.md). إشعارات المصادر والتراخيص في [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).

أهداف التداول الدائمة متاحة من لوحة «الأهداف» في ملف الوكيل، مع حدود الحجم والعمليات وتفعيل التداول التلقائي بواسطة المالك. تفاصيل التشغيل والاسترجاع في [docs/trading-goals.md](docs/trading-goals.md). طبّق ترحيل `0015_trading_goals` قبل تشغيل هذه النسخة.

## التشغيل المحلي

المتطلبات: Python 3.12، Node.js 22.22 أو أحدث، pnpm 11.25.0، وDocker مع Compose.

```sh
bash scripts/install.sh
bash scripts/dev.sh
```

التثبيت يحفظ إعدادات `.env` الموجودة ويولد مفاتيح الإعداد والتشفير الناقصة محليًا. يبدأ أمر التطوير PostgreSQL، يطبق الترحيلات، ويشغل FastAPI والواجهة المبنية على المنفذ 8000 والعامل المقيم. افتح واجهة الخادم، وأنشئ حساب المالك باستخدام `LONORA_BOOTSTRAP_TOKEN` الموجود في ملف `.env` الخاص. لا توجد كلمات مرور افتراضية أو تسجيل عام.

```sh
curl -fsS http://127.0.0.1:8000/health
curl -fsS http://127.0.0.1:8000/ready
```

تتحقق الجاهزية من قاعدة البيانات ونبض العامل المقيم. سجلات التشغيل في `.runtime/api.log` و`.runtime/gateway.log`. لتعديل Web مع التحديث الفوري شغل `pnpm --filter @lonora/web dev` بجانب الخادم؛ الوكيل لا ينفذ داخل Vite.

## توصيل النماذج والصوت والتداول

افتح إعدادات النظام لإضافة مفاتيح المزودين إلى مخزن الخادم المشفر، واكتشاف الكتالوج الرسمي، واختيار التوجيه العالمي. المزودون المعتمدون: OpenAI وAnthropic وDeepSeek وZ.ai وOpenRouter. إنشاء الوكيل يحتاج الاسم والصورة واللون فقط؛ تعليماته مستقلة، وإعداد النماذج عالمي.

[مسار الصوت](docs/GPT_LIVE.md) يستخدم GPT-Live وWebRTC مباشرةً؛ يتطلب مفتاح OpenAI يملك وصولًا إلى Live API، وتُفوّض المهام إلى نفس وكيل Lonora والمحادثة والأدوات. يتطلب التداول حساب MetaApi فعليًا أو بيانات محاكاة مستوردة صراحة. ضوابط OFF/ON والإيقاف الطارئ وسجل العمليات والمصالحة تُطبق على الخادم. لا يتضمن المشروع مفاتيح مزود أو حساب وسيط أو بيانات أسعار افتراضية.

## تطبيق Expo

```sh
pnpm dev:mobile
pnpm check:mobile
pnpm build:mobile
```

العميل يحتوي قائمة الوكلاء والمجموعات، الإنشاء، المحادثات والمرفقات، حالات التنفيذ والإلغاء والاستعادة، وتحرير الهوية والذاكرة والمجموعات والمهام المجدولة وسجلها، ومعاينة الملفات ومشاركتها، وقراءة الإعدادات العالمية والاستخدام. أدخل عنوان خادم يمكن للهاتف الوصول إليه بعد إنشاء حساب المالك عبر Web. جلسة Native محفوظة في SecureStore وقابلة للإبطال من الخادم؛ نسخة Expo Web تستخدم Cookies وCSRF.

`build:mobile` يصدر حزم JavaScript لـ Web وiOS وAndroid. إصدار تطبيق أصلي يتطلب Android SDK أو Xcode وجهازًا أو محاكيًا والتوقيع الخاص بك. السوق والصوت ولوحات المهام وتعديل المعرفة وإدارة الاتصالات متاحة حاليًا في واجهة Web الكاملة. التفاصيل والحدود في [apps/mobile/README.md](apps/mobile/README.md).

## التحقق والنشر

```sh
bash scripts/build.sh
bash scripts/migrate.sh
```

يشمل البناء Ruff وPyright وBiome وأنواع حزم Web/Expo وبناء Web وتصدير Expo للمنصات الثلاث. اختبارات CI الوظيفية تستخدم PostgreSQL ونماذج اختبار صريحة، وليست دليلًا على اتصال حسابات مزود أو وسيط حقيقية.

ملفات الإنتاج في `infra/compose/docker-compose.prod.yml`. بعد ضبط المجال العام وكلمات المرور والمفاتيح الخاصة:

```sh
bash infra/compose/deploy-main.sh --build
```

وضع `--build` يبني صورة الخادم من المصدر. وضع `--pull` يستخدم صورة السجل. صور الخادم تشمل Web وPython؛ حزم تطبيق الموبايل تُبنى بصورة مستقلة. يحتفظ مسار النشر بالنسخ الاحتياطية للبيانات والمرفقات ومفتاح التشفير؛ احفظها في موضع خاص. يمكن تمرير `--no-backup` عند طلب نشر دون إنشاء نسخة احتياطية؛ هذا الخيار لا يحذف الأرشيفات القديمة. لا تشغل أدوات تقوية المضيف على بيئة التطوير السحابية.

اختبارات العملاء والواجهة المحفوظة في المستودع:

```sh
pnpm test:clients
pnpm test:streaming
pnpm test:web
pnpm test:mobile
```

تتطلب هذه الأوامر تعيين `LONORA_DATABASE_URL` صراحة لقاعدة PostgreSQL مهاجرة ينتهي اسمها بـ `_ci` أو `_test` أو `_verify`، وترفض قاعدة التشغيل. اختبارات Web وExpo Web تشغل API اختبارًا مستقلاً على المنفذين 8830 و8831 وتبني نسخة StrictMode منفصلة داخل `.runtime`، وتحذف فقط العناصر التي أنشأتها. عند استخدام حساب اختبار موجود، اضبط `LONORA_UI_TEST_EMAIL` و`LONORA_UI_TEST_PASSWORD` في بيئتك الخاصة. تُستخدم بيانات CI الاختبارية فقط افتراضيًا، ولا توجد كلمة مرور تشغيل افتراضية. يمكن تحديد Chromium مثبت عبر `LONORA_UI_TEST_BROWSER_PATH`، أو تثبيت متصفح Playwright بواسطة `pnpm exec playwright install chromium`.

تُحفظ معاينة الرد الجاري مع رقم دور النموذج وسياج العامل وتسلسل المقاطع، وتستعيدها الواجهة بعد التحديث أو إعادة الاتصال. لا يزيل وصول الرد النهائي الرسائل الأقدم التي حمّلتها. طلبات البوتات ونتائجها تظهر في المحادثتين المستمرتين، وتستعيد خدمة المصالحة النتائج إذا انقطع العامل بعد إكمال المهمة. `test:streaming` يتحقق من هذه الضمانات على PostgreSQL، واختبارات Web تستخدم نفس الخادم مع نماذج اختبار صريحة.
