Any subscription sign-in implementation will trip it; the guard and its allowlists must be amended together with VISION.
3. **tests/test_model_providers.py** pins the wire contract: "the registry has exactly the six paths of 12.1", ALLOWED_HEADERS (anything but authorization / x-api-key / anthropic-version is "an assumption the key does not make"), and base URLs per provider. Subscription calls (different hosts, extra headers) break it by design.
4. **(2) is partly the opposite of what the code and a CI workflow say today.** `.github/workflows/model-catalog-update.yml` starts with "no guessed static model list is committed". The whole system derives the catalog by calling each provider's `/models` (discovery), stores it per provider in `ln_settings` key `catalog:<provider>`, and treats a model as assignable only if that stored catalog lists it. Several docs promise "any model of a connected provider's catalog". A fixed catalog touches discovery, router, default model, agent model choice tools, three routes, the Secret card submit, the web settings UI and ~12 test files (section 9).
5. **The "Automatic/Fixed mode, allowed list, agent_model card" the brief names no longer exist.** Migration 0131_agent_model_owner_only removed the modes, the `model_allowed` list and the `agent_model` / `agent_model_changed` cards (VISION 10.3 table line 491: "the owner's typed message assigns the model (12.3)"). Today's agent model choice is: one `AgentModelRecord` (primary + up to 3 fallbacks, `chosen_by` owner|inherited) plus the `model_request` / `model_list` tools. See section 5.
6. **Existing static tables already ship in code** and are the natural seed for a fixed catalog: `packages/providers/src/lonora_providers/model_windows.py` (context windows and output maxima per family), `packages/core/src/lonora_core/model_pricing.py` (Anthropic list prices only; OpenAI/DeepSeek/Z.ai/OpenRouter "could not be verified ... unpriced"), `default_model.py PREFERRED_FAMILIES`, `adapter_kit/tokenization.py`.
7. **Single-secret-string assumption.** The credential path returns `(api_key_string, base_url|None)` and adapters put one string into a header. An OAuth subscription token needs access token + refresh token + expiry + (for ChatGPT) an account id, refresh before expiry, rotation write-back, and different hosts/endpoints. That does not fit `ProviderCredentials.connection`, `BaseModelAdapter.auth_headers`, `credential_fingerprint`, or the `SecretStore` read-only-string contract without extension (section 8).
8. **Voice, embeddings and speech use the OpenAI *API key* directly** (`credentials.resolve("openai")` in voice/realtime/STT/TTS and `lonora_memory/semantic.py` -> https://api.openai.com/v1/embeddings). A ChatGPT subscription does not cover those; they must stay API-key based or be explicitly left out of scope.

`GlobalModelRouter` (packages/providers/src/lonora_providers/router.py):

## 4. Data flow: "owner adds a key" -> "agent turn uses model X"

1. Owner (or agent) triggers a Secret card: agent tool `owner_action_propose(target="model_provider", name=<id>)` -> card row (`OwnerActionRow`, table `ln_owner_actions`, kind `secret`, payload.connect=`model_provider`, details.provider) (secret_cards.py `secret_card_payload`).
2. Owner types key (and URL) on the web or mobile card -> `POST /api/owner-actions/{id}/secret` (routes/secret_cards.py:64).
3. Server: validate values -> `offered_models` -> **live `GET <base>/models`** (Anthropic paginated `limit=100`, up to 10 pages; OpenAI-compatible `data[]`) with the typed key -> txn: encrypt+store key (`ln_secrets`, scope workspace, name `OPENAI_API_KEY` etc.), write `ln_settings[model_provider:<p>]`, overwrite `ln_settings[catalog:<p>]`, settle card, wake agent.
4. `answer_unconfigured`: `router.usable_route(CONVERSATION)`; with no routing and a key, `choose_default_model` re-discovers, picks the first `PREFERRED_FAMILIES` match (openai: gpt-5.4-mini, gpt-5-mini, gpt-5, gpt-4.1-mini, gpt-4o-mini; anthropic: claude-sonnet-5, claude-sonnet-4-6, claude-sonnet-4-5, claude-sonnet-4; deepseek: deepseek-v4-pro, deepseek-flash, deepseek-chat; zai: glm-5, glm-4.7, glm-4.6, glm-4.5; openrouter: openrouter/auto; openai_compatible: first listed) and writes `model_routing.unified`. Then `retry_unconfigured` re-queues failed replies.
5. Owner may change the global choice: `GET/PUT /api/settings/models` (`RoutingPolicy` mode unified|custom, `unified`, `routes` per `Capability`), `PUT /api/settings/models/backups` (<=3), `GET/PUT /api/settings/models/context` (`ModelContextPolicy`): routes/model_router.py. Note: the PUT stores whatever `ModelSelection` it is given; it does NOT check the catalog.
6. Owner may assign a per-agent model: `PUT /api/agents/{id}/model` or in chat via `model_request` (section 5).
7. ## 6. Model adapters (HTTP)

Common: packages/adapter-kit/src/lonora_adapter_kit/model.py `ModelAdapter` Protocol: `complete(model, messages, tools, *, max_output_tokens, on_delta, allow_empty) -> ModelReply`, `discover() -> list[ModelDescriptor]`, `close()`. Types in adapter_kit/types.py (`ModelMessage`, `ModelReply`, `ToolCall`, `ToolDefinition`). Base: packages/adapters/src/lonora_adapters/models/base.py `BaseModelAdapter(api_key, base_url, client)`: httpx.AsyncClient timeout 90 s / connect 15 s, `follow_redirects=False`, `auth_headers()` Bearer (Anthropic overrides), `request()` (non-2xx -> `response_failure`, non-dict JSON -> `invalid_response`), `stream_request()` (SSE `data:` lines, `[DONE]`, line cap 1,000,000 chars, bounded error body 65536), `transport_failure`, `interrupted_stream`, `stream_error`, `stopped_reply`, `chosen_silence`.

### 6.1 OpenAI-compatible family (OpenAI, DeepSeek, Z.ai, OpenRouter, owner endpoint)
packages/adapters/src/lonora_adapters/models/openai_compatible.py `OpenAICompatibleAdapter`:
- **Chat Completions only**: `POST {base}/chat/completions`. **The OpenAI Responses API is NOT used anywhere** (grep for `/responses` finds nothing; docs/proposals/web-research.md refers to "OpenAI after its Responses path" as future work). ChatGPT-subscription backends are Responses-style, so a subscription adapter is a new wire format, not a header swap.
- Payload: `model`, `messages` (`wire_messages`: roles as-is, images as `image_url` parts, `tool_call_id`, assistant `tool_calls` with JSON-string arguments; adjacent user turns coalesced), `stream`, output cap `max_completion_tokens` for `provider == "openai"` else `max_tokens`, `tools` as `{"type":"function","function":tool.model_dump()}`. No reasoning-effort, temperature, tool_choice, response_format controls (docs/provider-resilience.md: "Reasoning/thinking controls ... are not configured per adapter").
- Streaming when `on_delta` is given: `stream:true`, `stream_options.include_usage`; accumulates content deltas (120,000 char cap), tool-call fragments by index (<=32 calls, args <=120,000), requires a `finish_reason` else `interrupted_stream` (a `stream_incomplete` CONNECTION failure); an `error` object mid-stream or a 200 with `error` -> `stream_error`.
- Tool calling: native `tool_calls`; arguments `json.loads`ed; a cut-off reply with tool calls is never returned (`stopped_reply` raises TRUNCATED).
- Usage: `prompt_tokens`, `completion_tokens`, `prompt_tokens_details.cached_tokens`.
- `discover()`: `GET {base}/models`, `data[]` with string `id`; OpenRouter capability parsing as in section 5; `context_length`; `source = base_url + "/models"`.

### 6.2 Anthropic
packages/adapters/src/lonora_adapters/models/anthropic.py `AnthropicAdapter`:
- **Messages API**: `POST https://api.anthropic.com/v1/messages`; headers `x-api-key`, `anthropic-version: 2023-06-01` (`auth_headers` returns only these; "Authorization is not sent at all").
- Payload: `model`, `max_tokens` (`max_output_tokens or 8192`), `messages` (`anthropic_messages`: system messages hoisted and joined; tool results as `tool_result` user blocks; images base64/url; same-role turns merged; assistant `tool_use` blocks), `system` via `cacheable_system` (prompt-caching `cache_control: ephemeral` on the immutable `<lonora_operating_policy>` prefix and adjacent native-visual block), `tools` as `{name, description, input_schema}`. No thinking/beta headers.
- Streaming: SSE events `message_start`, `content_block_start/delta` (text and `partial_json`), `message_delta` (`stop_reason`, usage), `message_stop` (required), `error`; same caps.
- Usage: `input_tokens`, `output_tokens`, `cache_read_input_tokens` (cache writes not recorded, see model_pricing docstring).
- `discover()`: `GET /v1/models?limit=100` paginated via `has_more`/`last_id`/`after_id` up to 10 pages; maps `display_name`, `max_input_tokens` -> `context_window`, `max_tokens` -> `maximum_output_tokens`; `verified=False`, no capabilities.

### 6.3 Others
`CompatibleEndpointAdapter` (owner base URL re-validated in the constructor), `fake.py` scripted test adapter, plus voice adapters (packages/adapters/src/lonora_adapters/voice/{realtime,stt,tts}.py) calling api.openai.com (live sessions, transcriptions, speech) with the API key.

### 6.4 Error taxonomy
packages/adapter-kit/src/lonora_adapter_kit/model_errors.py (adapts Hermes Agent `agent/error_classifier.py`, MIT; THIRD_PARTY_NOTICES.md): `FailureReason` = auth, permission, billing, rate_limit, overloaded, server_error, timeout, connection, context_overflow, payload_too_large, model_not_found, content_policy, format_error, output_limit, truncated, invalid_response, not_configured, unknown. `CODES` map each to a stable code/HTTP status (auth -> `model_credentials_rejected` 502; permission -> `model_access_denied`; billing -> `model_billing_exhausted`; rate_limit -> `model_rate_limited` 429; overloaded/server_error/timeout/connection/unknown -> `model_provider_unavailable` 502; context_overflow/payload_too_large -> `context_limit_exceeded` 413; model_not_found -> `model_endpoint_unavailable`; content_policy -> `model_content_blocked`; format_error/output_limit -> `model_request_rejected`; truncated -> `model_output_truncated`; invalid_response -> `model_response_invalid`; not_configured -> `model_not_configured` 409). `ModelProviderError(reason, http_status, retry_after, output_limit, provider_type, inferred)`. Classification: typed code/type, else HTTP status refined by message (`_by_status`: 401 AUTH, 402 BILLING, 403 refined by billing/content/invalid-key wording else PERMISSION, 404 MODEL_NOT_FOUND, 408/504 TIMEOUT, 413, 429 RATE_LIMIT/OVERLOADED/BILLING, 503/529 OVERLOADED, 5xx SERVER_ERROR, other 4xx by message else FORMAT_ERROR), then message patterns; `Retry-After`, `retry-after-ms`, "try again in Ns" -> `retry_after`; message text is never stored; `inferred` reasons never bench beyond a transient cooldown. `TRUNCATION_STOPS={max_tokens,length,model_context_window_exceeded}`, `REFUSAL_STOPS={refusal,content_filter}`. Subscription backends will return different error shapes (e.g. usage-window / plan-limit messages) that need mapping (billing vs rate_limit).

## 8. Implications for subscription sign-in (code-level observations, not decisions)

- Reusable: `packages/adapters/src/lonora_adapters/mcp/oauth.py` (`pkce_pair`, `authorization_url`, `exchange_code`; "called by nothing", docs/proposals/mcp-oauth.md section 1) and the MCP OAuth specification (docs/proposals/mcp-oauth.md; D45 confirmed) cover PKCE/callback/refresh/encrypted-token design for MCP servers, not for AI platforms. No public redirect/callback route for model sign-in exists.
- Interfaces that assume one static string: `ProviderCredentials.connection -> tuple[str, str|None]`, `SecretStore.read -> str`, `BaseModelAdapter.auth_headers`, router `credential_fingerprint(secret[+endpoint])`, AUTH handling (`AUTH` benches the credential for 900 s by fingerprint; a refreshed token changes the fingerprint, which is fine but means a bench reset), `PROVIDER_KEY_NAMES`/workspace secret injection (an OAuth token saved as a workspace secret would be injectable into agent commands; the secret-card path exposes keys to the workspace by design, VISION 7.2.5).
- Subscription backends: ChatGPT (Codex-style) and Claude subscription tokens use different hosts, extra headers/beta flags and (ChatGPT) the Responses wire format; Lonora has Chat Completions only for OpenAI. These are exactly what tests/test_model_access_guard.py and test_model_providers.py ALLOWED_HEADERS/PUBLIC_MODEL_HOSTS forbid.
- Per-card model of "Secret card" is the mandated sign-in surface (VISION 7.2; mandate 10.3 "five fixed cards"); an OAuth sign-in card would be a sixth kind or a new target of the Secret card (docs/proposals/mcp-oauth.md proposes a "sign-in card" for MCP; check VISION 10.3 before adding card kinds). Cards list in VISION 10.3 around lines 461-495.
- The Cloud plan (Amendment 3) says the operator "sells no model access"; subscription sign-in is the customer's own account and does not conflict with item 4 itself, but "Model access stays API keys the owner provides (section 12)" must be edited.
- Voice/embeddings/STT/TTS require OpenAI API keys regardless.

## 12. VISION section 6 (the invisible safety core) versus models/providers

Section 6 (VISION.md:289-325, "These are correctness guarantees ... They MUST be preserved through every refactor in this mandate") concerns the execution door, journal, preflight, serialization, exact approval, owner settlement, run integrity and provenance. It names no provider or model code, but these touch models:
- :319-321 (item 10, Provenance, [Adopted]): "Third-party content (web pages, feeds, files, peer messages, `lonora wake` text, workspace process output) reaches the model marked as data, never as instructions." and "A generated-interface element can never stand in for a fixed card. It cannot approve a Trade Approval, settle an operation, or switch a mode." and "A voice handoff or a generated-interface submission is input to the agent's own judgment ... In Full mode it never turns a decision into an approval card." => adapters/sign-in code must not let provider or token text become instructions; a model-sign-in card must not be a path to approve or settle trades.
- Item 7 (exact approval via `require_operation_permission`, `operation_id` plus `trade_fingerprint`) and item 9 (run lease `require_lease`, `require_task_authority`) are independent of which model answers; `model_request`/choosing a model "never grants authority" (agent_models.py docstring, docs/provider-resilience.md: "Choosing a model never grants authority: permissions, approvals and every execution boundary stay the agent's whatever model answers"). A catalog or sign-in change must not make model choice or a provider error reach `ExecutionService.execute`, widen `AgentModelPreference` into permissions, or relax `names_model`/owner-message gating of `model_request`.
- Item 3 "Never resend an uncertain order" and item 4 "Broker truth": router retries are only for model requests ("Nothing here repeats tool calls or external effects: a model request has none, and a reply whose tool input was cut off is never returned", router.py docstring). Keep: TRUNCATED never yields tool calls (`stopped_reply`), `model_recovery.py` replays only when every call without a result is a read or checkpoint. Any new adapter (Responses API, subscription backend) MUST keep these two properties (no tool calls from cut-off replies; no repeated financial effect on retry).
- Redaction (7.2.6, outside section 6 but safety-critical): subscription tokens and refresh tokens must be added to the scanned secrets so they never reach model context/logs/memory (`EncryptedSecretStore.scanned_values`).
- Section 6 forbids no model-provider feature; the amendment path (VISION "Owner amendments", Amendment 3 shape) is the owner's.
