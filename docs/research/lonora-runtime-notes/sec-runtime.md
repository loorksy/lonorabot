## Axis 2. The runtime

Code at `9f5b1da`. **safety** = refusal exists for a money rule and must stay. **UNSURE** = not confirmed. Causes only.

### 2.1 Processes, threads, bus, gateway

- Two processes: `api` (creates Runs, no background loop: `apps/api/src/lonora_api/app.py:86-96`) and `gateway` (all background work: `apps/worker/src/lonora_worker/main.py:11-23`), plus one-shot `migrate` and PostgreSQL (`entrypoint.sh:5-11`). Production healthcheck uses `/health` (database only), so a dead gateway leaves the api healthy (`infra/compose/docker-compose.prod.yml:49`). Defaults: lease 120 s, 24 rounds, 4 subagents (`apps/api/src/lonora_api/env.py:95-98`).
- `list_threads` returns only `purpose == "conversation"` (`packages/db/src/lonora_db/threads.py:98-100`): Task threads (`work`) are hidden; subagent and routine threads are `conversation` and appear beside the owner's chat (`packages/db/src/lonora_db/schema.py:227-229`).
- Bus: no external broker; the PostgreSQL events table, written in the business transaction and polled by cursor (`packages/db/src/lonora_db/events.py:104-122`): at-least-once replay from a client cursor, but a first live SSE mount starts at the present (`apps/api/src/lonora_api/routes/events.py:34-111`). The run queue is the `queued` status of Run rows.
- Gateway: `maximum_subagents + 1` shared run workers plus one conversation-lane worker (5 + 1) and 23 supervised maintenance steps (`packages/gateway/src/lonora_gateway/service.py:40-65`, `:290-301`). Items failing 5 times are quarantined (`packages/db/src/lonora_db/item_failures.py:26-32`). The watchdog (30 s, inside the gateway, never decides a trade) raises `gateway_degraded`, `run_quarantined` after 5 Run recoveries (held if a financial operation is unresolved, safety) and `operation_unresolved` after 15 minutes (`packages/gateway/src/lonora_gateway/watchdog.py:82-101`, `:219-336`). With the gateway down nothing is raised and a new owner Run stays `queued`; UNSURE what clients show.

### 2.2 Leases and concurrency

- `claim_next` takes `queued` Runs, or `leased/running` Runs with an expired lease and `recovery_count < 5`; skips a paused agent and a thread with an active Run (`packages/db/src/lonora_db/runs.py:194-206`, `:234-253`). Lease 120 s, renewed every third; if renewal keeps failing the lease is lost and the Run cancelled (`packages/agent-runtime/src/lonora_agent/executor.py:44-73`); writes are fenced and `stale_lease` never reaches the model (`packages/db/src/lonora_db/runs.py:297-311`).
- At expiry another worker restores the checkpoint; a non-read-only call in flight and not replay-safe is not re-run, the model gets `tool_execution_uncertain` (`packages/agent-runtime/src/lonora_agent/tool_dispatch.py:82-95`; safety). After 5 recoveries: `run_recovery_limit` (`packages/db/src/lonora_db/runs.py:529-577`).
- Concurrency: one live Run per thread; none per agent; global = worker count; background triggers never use the conversation worker (`packages/db/src/lonora_db/runs.py:224-228`).
- A second owner message during a run is folded into the active conversational Run, never a second Run (`packages/db/src/lonora_db/messages.py:516-525`): `queued` -> input moves; `leased/running` -> steering row read at the next boundary, unstarted calls closed `tool_call_superseded` (`packages/agent-runtime/src/lonora_agent/tool_loop.py:353-361`); `waiting_input` -> question answered, Run requeued. Against background work a new `user` Run queues behind it. A new message withdraws an approved unsent trade (`packages/tools/src/lonora_tools/trade.py:446-447`; safety). The owner is never told "busy".

### 2.3 Tasks

- A Task is a ticket row with its own hidden `work` thread and Run (`packages/db/src/lonora_db/tasks.py:169-226`); `task_start`: "Neither mode grants trading authority; never report invented progress." (`packages/tools/src/lonora_tools/tasks.py:105-111`). States `queued, running, waiting, paused, completed, failed, cancelled`; recovery `automatic, owner, reconcile, modify_plan, terminal` (`packages/contracts/src/lonora_contracts/tasks.py:10-12`). Advanced by run workers, steps `task_waits` (5 s), `task_retries` and `outcomes` (10 s) (`packages/db/src/lonora_db/task_wait.py:167-232`), and owner pause/resume/cancel/revise (`apps/api/src/lonora_api/routes/tasks.py:54-73`).
- Budgets: 24 rounds per slice, up to 4 slices for a Task Run (`packages/agent-runtime/src/lonora_agent/continuation.py:20-27`); an external wake resets rounds, a restart does not (`packages/db/src/lonora_db/task_wait.py:138-150`); stop gates nudge at most twice, then hand to the owner (`packages/agent-runtime/src/lonora_agent/stop_gates.py:41`). `due_at` is "A target, not a trigger." and is never compared with the clock (`packages/contracts/src/lonora_contracts/tasks.py:49-51`). Steps complete only with ids of real successful calls (`packages/db/src/lonora_db/tasks.py:703-752`; safety).
- Waits: `watch`, `broker_recovery`, `timer` (5 s to 7 days) (`packages/contracts/src/lonora_contracts/tasks.py:109-112`). The watch's enabled state is checked only at admission (`packages/db/src/lonora_db/task_wait.py:32-42`): a watch that later expires, is paused, cancelled or quarantined leaves the Task `waiting` for ever; the watchdog counts only overdue timer waits (`packages/gateway/src/lonora_gateway/watchdog.py:266-275`).
- Failure: unresolved financial/non-read-only call -> `reconcile` (never retried automatically; safety); `model_request_rejected`, `context_limit_exceeded`, `tool_round_limit`, `task_steps_incomplete`, `task_wait_required` -> `modify_plan`; transient -> `owner` or `automatic`; else `terminal` (`packages/db/src/lonora_db/task_recovery.py:25-33`, `:119-181`, `:323-331`). Default 3 attempts (`packages/contracts/src/lonora_contracts/tasks.py:15-18`).
- Owner sees on failure: no chat message (`packages/agent-runtime/src/lonora_agent/collaboration/outcome_return.py:128-153`); one item `task_review`, «المهمة تحتاج مراجعة», off-app «تحتاج المهمة إلى مراجعتك. افتح المحادثة لفحص سبب التوقف وخيارات الاستكمال.» (`packages/bus/src/lonora_bus/attention_messages.json:7`), no reason (`apps/web/src/components/ai/AttentionInbox.tsx:114-121`). The Task page shows `failed` and `waiting` alike as «بانتظار المراجعة», with no reason or steps (`apps/web/src/shell/domain/TasksPages.tsx:40-42`, `:194-203`). Resume is refused for `modify_plan`, `terminal`, `reconcile/external`: "This task cannot resume in its current state. Review its plan or retry limit." (`packages/db/src/lonora_db/task_recovery.py:236-246`, `apps/web/src/lib/user_error.ts:214-216`). The API accepts `revise` (`apps/api/src/lonora_api/routes/tasks.py:54-59`) but no web or mobile caller sends it. UNSURE whether the agent can reach `task_control`: not among the 23 native tools offered in production; the one `tool_environment` query ("watch cancel task routines goals", 10:53:57 UTC) returned an empty list.
- At a work limit, spent nudges or a long model outage the Run waits with an `owner_attention` question (`packages/agent-runtime/src/lonora_agent/loop_outcomes.py:109-152`). Texts (`packages/agent-runtime/src/lonora_agent/runtime_notices.py:142-169`): «هذه المهمة لم تكتمل بعد.»; «هذه المهمة المستمرة غير مراقَبة: لم يُحفظ أي انتظار مراقبة أو مؤقت مراجعة، لذلك لن تحدث أي متابعة تلقائية.»; «توقفت هذه المهمة قبل اكتمالها لأن هذه الجولة بلغت حدّ العمل، ولم يُنفَّذ أي إجراء بعد ذلك.»; «توقفت هذه المهمة قبل اكتمالها لأن استدعاء أداة تكرر دون تقدّم، ولم يُنفَّذ أي إجراء بعد ذلك.»; «هذه المهمة معلّقة لأن كل النماذج المهيأة غير متاحة منذ مدة رغم المحاولات المتكررة؛ تقدّمها محفوظ ولم يُكرَّر أي إجراء.» Each ends «أحتاج توجيهك قبل المتابعة: ردّ هنا، أو عدّل المهمة أو استأنفها أو أوقفها مؤقتًا أو ألغها.» (`packages/agent-runtime/src/lonora_agent/runtime_notices.py:190-195`).
- That text goes to the hidden work thread (`packages/agent-runtime/src/lonora_agent/executor.py:176-187`); its item belongs to the origin conversation (`packages/gateway/src/lonora_gateway/attention.py:271-281`) but the web link opens `/app/<agent_id>` with no thread (`apps/web/src/components/ai/AttentionInbox.tsx:123-130`), i.e. the saved thread, else the oldest (`apps/web/src/hooks/usePersistentThread.ts:58-66`); UNSURE it is the origin. An owner message steers only a Run in its own thread (`packages/db/src/lonora_db/messages.py:516-525`), so «ردّ هنا» cannot be answered from the origin. An ordinary Task `wait_for_input` is posted there too, with no item (`packages/core/src/lonora_core/attention.py:7-35`). Completion is an `informational` item, off by default (`packages/core/src/lonora_core/attention.py:115-116`).

### 2.4 Routines

Exactly one of `interval_seconds` (60 to 31536000), `cron` + `timezone` (default `"UTC"`), one-shot `run_at` (`packages/contracts/src/lonora_contracts/routines.py:13-48`). Step every 5 s, up to 30 due per pass (`packages/automation/src/lonora_automation/runner.py:6-20`); a fire adds a Run `trigger="routine"`, scope `full`, without checking the previous Run (`packages/db/src/lonora_db/routines.py:188-202`). Missed recurring fires collapse into one late fire (`packages/db/src/lonora_db/routines.py:233-236`); a one-shot fires whenever next seen due (`:214-217`). A non-goal routine replies in its own new thread (`packages/db/src/lonora_db/routines.py:67-70`); the schedules page has no result view; no item when a routine Run completes or fails. Five firing errors disable it (`packages/db/src/lonora_db/routines.py:151-156`).

### 2.5 Watches

- Kinds `price, indicator, position, account, calendar, dynamic`; conditions `above, below, cross_above, cross_below, changed, closed, opened, due` (`packages/contracts/src/lonora_contracts/market_watch.py:15`, `:24-26`). Poll every 2 s, 200 per pass, 20 s per observation (`packages/gateway/src/lonora_gateway/service.py:56`, `packages/market/src/lonora_market/watchers.py:430-444`); `interval_seconds` default 30 (min 5), `cooldown_seconds` default 300 (min 30) (`packages/contracts/src/lonora_contracts/market_watch.py:30-31`). No per-agent creation limit found (`WATCH_LIMIT = 8` only caps the operational-state listing, `packages/db/src/lonora_db/operational_state.py:55`). It "wakes this agent to reassess and never trades" (`packages/tools/src/lonora_tools/market_watch.py:237-244`); one fire per observation (`packages/market/src/lonora_market/watchers.py:632-637`); an ordinary watch creates a Run `trigger="watch"` in its thread (`:675-701`), a Task-owned watch none (`:654-677`).
- `watch_create` validates shape only, no broker call or catalog lookup (`packages/tools/src/lonora_tools/market_watch.py:90-145`). At evaluation a broker error is caught, written as a health record, and the call returns normally (`packages/market/src/lonora_market/watchers.py:517-539`), so the watch is never quarantined (`packages/db/src/lonora_db/item_failures.py:124-143`) and its only signal, `watch.suspended_health`, is suppressed (`packages/db/src/lonora_db/attention.py:143-144`). Not exercised in production: the four watches were all `EURUSDm`, none on `XAUUSDm`.
- Other silent ends: five errors outside the observation -> `watch_quarantined` (`packages/market/src/lonora_market/watchers.py:59-66`); goal ended/plan changed or owning Task ended -> `enabled: False`, no event (`:490-500`, `:658-665`). ### 2.6 Wakes

- Sources of background Runs: `routine`, `watch` and opportunity transitions, `tickets`, `broker_event`, `activation`, `goal`, `subagent`, `peer`/`follow_up`, `webhook` (`packages/contracts/src/lonora_contracts/runs.py:7-9`, `apps/api/src/lonora_api/routes/webhook.py:16-34`). Dedupe by receipts: webhook nonce, watch observation, Task wake (`packages/agent-runtime/src/lonora_agent/automation/webhooks.py:13-20`, `packages/market/src/lonora_market/watchers.py:636-637`, `packages/db/src/lonora_db/task_wait.py:115-123`).
- Quiet hours hold only agent-raised alerts (`owner_notify`), all but `critical` (`packages/db/src/lonora_db/attention.py:425`, `:467-469`); server items have no check; wake Runs still run. `owner_notify`: 6 per agent per hour, then `owner_notify_rate_limited` (`:335`, `:396-397`).
- Authority: scope `helper` for subagents, `observe_only` when metadata says so, else `full`; no financial tool outside `full` (`packages/tools/src/lonora_tools/base.py:53-58`, `:92-97`; safety). Money in a routine/watch Run follows the signed grant and limits at the executor (`docs/proactive-wakes.md:33-35`). A wake Run may call `wait_for_input` (`packages/agent-runtime/src/lonora_agent/tool_block.py:370-393`); the question goes to its thread, no item.
- A failed wake Run: `run.failed` is not an attention kind; `return_outcome` writes to the origin only for `broker_event`, `activation`, opportunity watches, and only with a result (`packages/agent-runtime/src/lonora_agent/collaboration/outcome_return.py:164-185`); the web error card needs trigger `user`/`group` (`apps/web/src/lib/failed-replies.ts:3-10`); manual retry refuses it (`packages/db/src/lonora_db/run_retry.py:91-98`); a watch's trigger is already consumed (`packages/market/src/lonora_market/watchers.py:703-715`). Work Runs retry a model outage 30 s to 900 s, 6 failures (about 15 minutes); a missing model fails at once (`packages/agent-runtime/src/lonora_agent/model_recovery.py:61`, `:174-175`).

### 2.7 Subagents and peers

`subagent_spawn` returns at once with a queued Run in a new thread (`packages/agent-runtime/src/lonora_agent/collaboration/subagents.py:48-68`). Limits: depth 2, `maximum_subagents` active children else `subagent_limit` (`:22-47`), one slice of 24 rounds. Tools: read-only plus `workspace_execute` and `artifact_create`; no financial tool, memory write, peer message or `wait_for_input` (`packages/tools/src/lonora_tools/base.py:46-50`, `:92-97`; safety). The outcome `<peer_outcome ...>` + `child.result or child.error_code or status` is written to the parent thread (`packages/agent-runtime/src/lonora_agent/collaboration/outcome_return.py:216-229`): parent active -> steering; `waiting_input` -> requeued; completed -> a `follow_up` Run; failed/cancelled -> nobody reads it (`:245-274`). A failed child with no result shows its raw code (`model_provider_unavailable`, `runtime_error`, `run_recovery_limit`) as an assistant message in the owner's chat (`:217-244`); UNSURE of web rendering. Not exercised in production: `subagent_spawn` was not offered (`peer_send` was). A child crashing 5 times gets `run_quarantined` (`packages/gateway/src/lonora_gateway/watchdog.py:219-247`).

### 2.8 Crash, restart, server update

- SIGTERM: 25 s drain, leases returned `queued` with `reason_code: gateway_drained` (`packages/gateway/src/lonora_gateway/shutdown.py:8-14`, `packages/db/src/lonora_db/runs.py:490-526`); production `stop_grace_period` 40 s (`infra/compose/docker-compose.prod.yml:67-80`). Hard kill: up to 120 s until re-claim (`packages/db/src/lonora_db/runs.py:197-201`).
- Survives (database): Run checkpoint (`packages/db/src/lonora_db/runs.py:330-333`), Task state, all timers (`packages/db/src/lonora_db/routines.py:107`, `packages/market/src/lonora_market/watchers.py:410-412`), effect receipts, pending approval and question rows. Lost or delayed: the in-flight model request (repeated, `packages/agent-runtime/src/lonora_agent/tool_loop.py:329-339`); an unreceipted mutating call (uncertain, not re-run; safety); per-owner broker/voice objects (rebuilt, `packages/gateway/src/lonora_gateway/service.py:144-157`); watch observations during downtime (`packages/market/src/lonora_market/watchers.py:576-580`). The owner is not told (`packages/db/src/lonora_db/runs.py:517-525`).
- Production 2026-11-11: three updates (09:54:57, 10:23:46, 10:38:12 UTC) each stopped the API and gateway and recreated the containers; they cost one run an eight-second wait. Container logs before 10:37 UTC are gone. Nine `GET /api/agents/<the agent>/super-bot` requests answered 404 (10:50 to 10:53 UTC); no client on main calls that route (probably a cached old client). The database export of runs, tool calls and offered tools awaits owner approval and must confirm these per-run facts.

### 2.11 Reaching the owner proactively
