# خطة نقل واجهة Lonora إلى Tampletgrok

تستبدل هذه الخطة هيكل واجهة Web الحالي بواجهة مستمدة فعليًا من `loorksy/Tampletgrok`، وتربطها بواجهات Lonora الحقيقية في Python. المرجع هو القالب عند المراجعة `20fc9ac862bb833d1578968a7aba5ea18ff88a29` وتقرير الواجهة المرفق `Tampletgrok-UX-Report-EN.md`. تبقى رؤية Lonora وواجهات الخادم مرجعًا لسلوك الميزات.

القالب يقدم الشاشات والتفاعل، لكنه يعمل افتراضيًا ببيانات ومحاكاة محلية. نجاح النقل يعني تشغيل هذه الشاشات على بيانات Lonora، مع بقاء العامل المقيم والأحداث والذاكرة والتداول والصوت على الخادم.

## النتيجة المطلوبة

يفتح المستخدم آخر وكيل كان يعمل معه. تعرض الشاشة قائمة الوكلاء والمجموعات، المحادثة الدائمة، ولوحة سياق قابلة للفتح بجانبها. يفتح اسم الوكيل إعداداته، وتعرض لوحة العمل المعرفة والمهام المجدولة والسوق والتداول بحسب السياق. تبقى إعدادات النماذج والمزودين والصوت والتكاملات عالمية داخل إعدادات النظام.

تكون العربية اللغة الأولى مع دعم الإنجليزية، وتبقى الرموز والأسعار وأسماء النماذج والروابط معزولة باتجاهها الصحيح. يظهر اسم **Lonora** في التطبيق، والعناوين، ومفاتيح التخزين، والحزم، وإعدادات الموبايل.

## المسارات والتنقل

المسارات المرجعية لمساحة العمل هي `/app`، و`/app/:agentId`، و`/app/g/:groupId`. يمكن فتح الملفات واللوحة والبحث والنشاط والسوق والتداول عبر مسارات معلومة أو لوحة سياق مرتبطة بعنوان المحادثة. يُحسم الاسم النهائي للمسار في التنفيذ ويُحفظ الوصول المباشر إليه وإعادة التحميل عليه.

- `/app` يعيد المستخدم إلى آخر سياق صالح له، أو يعرض حالة فارغة بها إنشاء وكيل.
- تغيير الوكيل أو المجموعة يغلق طبقات الإنشاء المؤقتة وقائمة الهاتف.
- الرجوع على الهاتف يغلق الطبقة العليا أولًا، ثم ينتقل إلى المسار السابق.
- `Escape` يغلق اللوحة أو الحوار الأعلى، ويعيد التركيز إلى الزر الذي فتحه.
- المسار أو المعرّف غير الموجود يعرض رسالة مترجمة وروابط للعودة، ولا يترك شاشة فارغة.
- `Ctrl/Cmd+K` يتيح البحث أو تبديل الوكيل، مع زر مرئي لنفس الوظيفة.
- تفضيلات الواجهة المحلية تُعزل حسب المالك؛ الأسرار وجلسات الخادم لا تُحفظ داخل تفضيلات الواجهة.

## ما يُستبعد من القالب وفق رؤية Lonora

لا تُنقل شاشات الفوترة والاشتراك، والتسجيل العام، وSSO، والتحديثات الخاصة بتطبيق Desktop، والحاسوب الافتراضي أو Terminal أو وضع التعليم بالمشاهدة. لا يُضاف نموذج أو مزود أو وسيط مستقل لكل وكيل، ولا طبقة إلزامية للموافقة على كل صفقة. مساحة العمل التي كانت تعرض «Computer» تُكيف لعمل الوكيل ومعرفته وروتينه وسوقه.

كما لا تُستورد `packages/mock-adapters` أو جلسة العرض التلقائية أو كتالوج النماذج التجريبي. لا تتصل نسخة Lonora بـ`/rpc/<procedure>` الخاص بالقالب؛ يُستخدم API النظام الحالي. أي قدرة تحتاج مزودًا أو وسيطًا غير مُعد تعرض حالة إعداد واضحة، دون إنشاء أسعار أو رسائل أو نتائج تداول اصطناعية.

## مراحل التنفيذ والدفع إلى main

1. **تثبيت المرجع والعقود:** توثيق مراجعة القالب، مراجعة الترخيص، وحصر انتقال كل وظيفة إلى موضعها الجديد. يعتمد هذا المستند كخطة قابلة للمراجعة.
2. **استبدال هيكل Web:** نقل الهيكل والمكونات المناسبة فعليًا، وإضافة مسارات الوكلاء والمجموعات وقائمة الهاتف ولوحة السياق والاختصارات. توصيل الإنشاء والاختيار والخروج والرسائل إلى Lonora. يُدفع بعد نجاح بناء TypeScript وتجربة التنقل الأساسية.
3. **إكمال مساحات العمل:** توصيل المعرفة والعمل المفتوح والروتين والنشاط والبحث والملفات واللوحة والسوق والتداول والإعدادات إلى الهيكل الجديد. نقل شاشات الإعداد إلى مواضعها في تجربة القالب، مع إزالة المسارات المرئية القديمة الزائدة. يُدفع بعد التحقق من الوظائف الفعلية وحالات الفشل.
4. **العربية والجوال وإصلاحات التقرير:** استكمال الترجمة والاتجاه والتركيز والرجوع والعرض الوسيط والملفات. يُدفع بعد فحص أحجام الهاتف والتابلت وسطح المكتب وتسجيل الدخول والخروج.
5. **تطبيق Expo:** إضافة `apps/mobile` كعميل Lonora حقيقي به هوية Lonora وجلسة آمنة وقائمة وكلاء ومجموعات ومحادثة وإعدادات أساسية. يُدفع بعد فحص الأنواع والتوافق وتصدير الحزم؛ تبقى الميزات الأصلية غير المختبرة موثقة بحدود التحقق.
6. **التوثيق والتشغيل:** تحديث تعليمات التشغيل والبناء وإعداد البيئة، وتسجيل الفحوص المنفذة والمراجعات المدفوعة. لا يُعتمد نجاح خدمة خارجية لم تختبر بمفاتيح فعلية أو نجاح جهاز لم يُشغّل.

كل مرحلة يجب أن تترك المشروع قابلًا للبناء. إذا تجاوز تغيير حدود الواجهة إلى الخادم، تُفحص مسارات المصادقة والأحداث والتنفيذ المتأثرة، وتُحفظ البيانات الموجودة والترحيلات.

## نطاق Expo والتحقق

طلب المستخدم الأخير يفتح نطاق Expo بعد أن كان الموبايل مؤجلًا في الملفات السابقة. يشارك التطبيق Backend والهوية ومنطق الوكيل والتوجيه العالمي والتداول، ويستخدم نمط القالب الأصلي: Inbox أولًا، المحادثة شاشة مستقلة، الإنشاء Modal، والإعدادات Sheet.

أولوية العميل الأول: إعداد عنوان الخادم، الدخول والخروج واستعادة الجلسة وإبطالها، قائمة الوكلاء والمجموعات، إنشاء وكيل، المحادثات والرسائل وحالة التنفيذ والإلغاء، والعرض العربي. تبقى مفاتيح المزودين والوسيط على الخادم؛ تُحفظ بيانات الجلسة الحساسة على Native باستخدام SecureStore. لا تُخزّن أسرار المزودين في متغيرات `EXPO_PUBLIC_*`.

يجب فصل Web عن SecureStore وNotifications وأي واجهة Native غير متاحة، وفحص توافق حزم Expo وReact Native. فحص TypeScript وتصدير حزم iOS/Android يثبت قابلية تجميع JavaScript، لكنه لا يثبت الصوت أو الميكروفون أو الإشعارات أو عمل التطبيق على جهاز. يحتاج الادعاء بجاهزية إصدار متجر إلى Build أصلي واختبار جهاز أو محاكي وتوقيع الإصدار.

## الترخيص والهوية

تُزال الهوية السابقة من النصوص المعروضة، والعناوين، وأسماء الحزم، ومفاتيح LocalStorage أو SecureStore، وأسماء CSS وDOM، والرؤوس، ومخطط الروابط، ومعرفات التطبيق. تُستبدل العلامة الرسومية السابقة بهوية Lonora.

تُحفظ نسخة Apache-2.0 وإشعارات الحقوق والنسب المطلوبة في ملفات الترخيص القانونية، ومنها `LICENSE` و`THIRD_PARTY_NOTICES.md` مع نسب استخراج القالب. الاحتفاظ القانوني بالنسب لا يعيد الاسم السابق إلى هوية التطبيق أو واجهته. تُزال التعليقات التشغيلية القديمة مثل أمر توليد Tokens باسم حزمة قديم، وتُحدّث أمثلة المطورين إلى Lonora.

## قائمة القبول النهائية

- يمكن تشغيل Web الجديد من خادم Lonora الحالي، ولا توجد تبعية تشغيلية على Mock Adapters أو API القالب.
- إنشاء الوكيل وتحديثه والمحادثة والمجموعة والروتين والملفات والنشاط تستخدم البيانات الحقيقية وتبقى بعد إعادة التحميل.
- الرسالة أثناء التنفيذ تستخدم Steering الحالي؛ نتائج الأدوات وحالات الفشل والإلغاء تستند إلى Run الفعلي.
- يستطيع المستخدم الوصول إلى جميع وظائف Lonora القائمة من الهيكل الجديد، بما فيها Boards والمعرفة والسوق والتداول والصوت.
- إعداد النماذج عالمي واكتشافها ديناميكي؛ إنشاء الوكيل لا يحتوي نموذجًا أو وسيطًا أو إعداد مخاطرة.
- التشغيل مستمر في Worker عند إغلاق المتصفح؛ لا تنقل الواجهة وظيفة runtime إلى الجهاز.
- الهاتف والتابلت وسطح المكتب قابلة للاستخدام، مع العربية وRTL والرجوع والإغلاق والتركيز وحالات الفراغ والفشل.
- لا يوجد اسم أو أصل بصري لمنتج سابق داخل تجربة Lonora أو مفاتيح تشغيلها؛ تُحفظ النسب في موضعها القانوني.
- تنجح فحوص Web والأنواع والبناء، والفحوص الخلفية المناسبة لأي تعديل في API؛ تُوثق قيود CI الخارجي أو اختبار الأجهزة الفعلية إن بقيت.

هذا المستند خطة التنفيذ ومعايير القبول. يسجل التسليم النهائي ما نُفذ وما اختُبر ومراجعة Git المرتبطة به، ولا يحول مرحلة مخططة إلى ميزة جاهزة بلا تحقق.

## حالة التنفيذ والتحقق

نُفذ استبدال Web فعليًا ودُفع إلى `main`: الهيكل بثلاث مناطق، قائمة الوكلاء والمجموعات، المحادثة المستمرة، لوحة السياق المتجاوبة، الإعدادات العالمية، الإنشاء، البحث، الملفات، Boards وTickets. نُقلت مكونات القالب وعرض الصور الرمزية والمحادثة، وأزيلت الهوية التشغيلية السابقة مع الاحتفاظ بإشعارات الترخيص. وظائف المعرفة والمهارات والمراقبات والسوق والمخططات والتداول والصوت متصلة بخدمات Lonora القائمة.

أُضيف `apps/mobile` بعميل Expo حقيقي للقائمة والمحادثات والإنشاء والمرفقات وحالات التشغيل. تتشارك واجهتا Web وNative مسار فتح المحادثة الذري `/api/agents/{agent_id}/conversation`، فتعود الطلبات المتزامنة إلى المحادثة نفسها دون حذف السجل السابق. يستخدم Native جلسة خادم قابلة للإبطال في SecureStore، ويبقى Web على Cookies وCSRF.

التحقق المنفذ: بناء Python/Web وتصدير Expo للمنصات الثلاث، Ruff وPyright وBiome والأنواع، توافق SDK وPeer dependencies؛ 18 فحصًا على Web المبني؛ اختبارات فعلية لأول حساب والدخول والخروج؛ اختبارات الملفات والبحث والتذاكر والعرض عند 375–390px و800px؛ واختبارات تزامن ومصادقة على PostgreSQL. حُفظت أربعة اختبارات Playwright تعمل على API حقيقي وReact StrictMode، و11 فحصًا للعملاء والتزامن في `tests/check_clients.py`، وأضيف تشغيلهما إلى CI. يشمل اختبار الاستجابة المفقودة إعادة المحاولة بعد قبول الخادم للرسالة، دون تكرار الرسالة أو تشغيلها، مع بقاء الإرسال المقصود الجديد مستقلًا.

اختُبرت صورة الخادم محليًا مع قاعدة PostgreSQL فعلية، وخدمة Web المبنية ومسارات إعادة التحميل، ومستخدم الحاوية غير الجذر. GitHub Actions ونشر صورة السجل لم يعملا في الحساب الحالي بسبب قفل مرتبط بالفوترة؛ نجاح التحقق المحلي لا يعني نجاحهما. يمكن بناء المصدر بواسطة مسار النشر `--build`.

Expo هنا تطبيق مرافق، وليس إصدار متجر موثّقًا. نجح التصدير والاختبار عبر المتصفح؛ يبقى اختبار جهاز أو محاكي أصلي وتوقيع Android/iOS مطلوبًا قبل نشر تطبيق أصلي. لم تُختبر مفاتيح مزودين أو حساب وسيط حقيقي؛ اتصالها يتم من إعدادات الخادم.

تم توثيق مراجعة حدود الملفات والوظائف بعد توضيح أن الشجرة مرجع وظيفي وليست شرط نسخ حرفي في [FRONTEND_STRUCTURE.md](FRONTEND_STRUCTURE.md). تبقى محادثة وكيل التداول هي مركز النظام، والكمبيوتر السحابي خارج نطاق Lonora.
